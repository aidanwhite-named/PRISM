# 검색 프롬프트 최소 롤백과 동일 조건 비교

## 변경 범위

`backend/app/retrieval/prompts.py`의 `[검색 요령]`에서 종속항 해석을 위해 추가했던 공통 지시 5줄만 제거했다. 검색 시스템 프롬프트는 정상 과거 실행의 내용과 SHA-256까지 일치한다.

- 제거 전: `9561bcb3ab01a94356e8f2811a8390b1156f644d0e62aeaed3b0afe6c9ca6482`
- 제거 후: `afa6a256b6b89f5ecb06afc0c373b3523820e243a4664e3629662495f97713bf`

모델 혼잡 분류·제한 재시도·호출별 출력 파일 격리와 선행항 원문 전달은 유지했다. 단락 파서, 검색 예산, 근거 보존 로직, 구성 누락 검사는 변경하지 않았다. 이전부터 작업 중이던 다른 변경도 보존했다.

## 비교 방법

문제가 보고된 실행 `69911dce-8b35-406e-9aeb-f3ad0b122f16`의 청구항 1, 첨부 4건, 검색 예산, 의미 검색 활성 상태, 최종 분석 프롬프트를 고정했다. `codex / gpt-5.6-luna`로 제거 전과 제거 후를 각각 한 번씩 순차 실행했다. 최종 분석 추론 강도는 원 실행과 같은 `medium`이다.

- 원본 DB는 읽기 전용으로 열고 PDF 해시를 검증한다.
- 원본 단락 색인을 각각 복제하고 재색인이 일어나지 않았는지 검사한다.
- 제거 전 첫 검색 라운드의 payload가 원 실행과 완전히 같음을 확인했다.
- 최종 분석 입력은 원 실행의 근거 패키지 문자열만 새 검색 결과로 교체한다. 나머지 사용자 입력이 동일함을 검사한다.
- 제품 이력에 비교 결과를 추가하지 않고 `%LOCALAPPDATA%/PRISM/validation/prompt-rollback-20260918/{before,after}`에 저장한다. 운영 서버 재시작은 하지 않는다.
- 비교 스크립트와 입력 해시·집계는 `data/validation/prompt-rollback-20260918/`에 보존한다.

이 비교는 소표본 관측이다. 모델 출력의 변동성 때문에 점수 상승이나 한 번의 성공만으로 인과관계 또는 전체 품질 회복을 판정하지 않는다. 전제부의 포함, 실제 단락 인용, 한국 문헌 11쪽 아틀라스 근거의 최종 전달 여부를 우선 확인한다.

## 회귀 테스트

`tests/test_retrieval_capacity.py`, `tests/test_codex_provider.py`, `tests/test_retrieval_scope_fixes.py`: **64개 통과**. 롤백 뒤에도 혼잡 처리·출력 격리·선행항 입력 경계 관련 동작을 확인했다.

## 실제 검색 비교 결과

전후 첫 라운드 payload는 완전히 같았고, 네 문헌의 `(chunk_id, paragraph, text)` 내용 해시도 모두 같았다. 검색 시스템 프롬프트 5줄만 달리했다. 두 실행 모두 5라운드를 사용했다.

| 관측 항목 | 원래 문제 실행 | 제거 전 재실행 | 제거 후 재실행 |
| --- | --- | --- | --- |
| 검색 모델이 선언한 구성 | A~F 6개 | A~F 6개 | A~F 6개 |
| 전제부를 별도 구성으로 보존 | 없음 | 없음 | 없음 |
| `read_chunk` 요청 | 20회 | 15회 | 24회 |
| 최종 한국 문헌 원문 페이지 | 5, 9, 12 | 5, 9, 12 | 없음 |
| 한국 문헌 11쪽 아틀라스 원문 전달 | 없음 | 없음 | 없음 |
| 최종 근거 문자 수 | 97,641 | 99,847 | 58,537 |
| 미처리 이월 요청 | 9 | 12 | 0 |

제거 후 실행은 최종 `finalize_evidence`에서 A·E에만 ATT-03의 세 구간을 선정했고 B·C·D·F는 `not_found`, 빈 근거로 제출했다. 검증기에서 거부한 근거와 action 오류는 모두 0건이다. 예산 초과로 한국 문헌을 잘라낸 것이 아니라 모델이 마지막 선정에서 제외한 결과다. 미처리 요청이 0건이어도 충분한 근거 전달을 의미하지 않는 사례다.

제거 후에도 그 전에 한국 문헌 `P0005-001`, `P0009-002`, `P0009-003` 등을 열람했다. 마지막 호출에서 구성 C의 후보 목록은 `P0009-001`의 360자 발췌만 보존했고, 구성 D의 한국 문헌 후보는 첫 페이지 서지정보 발췌였다. 이미 열람한 기술 구간 전체가 최종 선정에 자동 보존되는 구조가 아니라는 진단과 일치한다. 이것이 모든 미선정 근거의 기술적 대응을 입증하는 것은 아니다.

또한 제거 전 재실행 보고서는 같은 단락 색인으로 한국 문헌 `[0003]`을 인용했다. 이전 문제 보고서의 페이지 인용만으로 단락 파서가 이번 수정으로 깨졌다고 볼 수 없으며, 본문의 번호를 모델이 직접 이용하는 동작에는 변동성이 있다.

## 최종 보고서 확인

두 실행 모두 최종 provider 종료 코드 0, 오류·도구 호출·승인 거부 없이 완료됐다. 검색 5라운드는 각각 1회 시도로 성공해 혼잡 재시도는 한 번도 사용되지 않았다.

| 보고서 구성 | 제거 전 재실행 | 제거 후 재실행 |
| --- | --- | --- |
| 전제부 | 누락 | 누락 |
| A | 55% | 55% |
| B | 35% | 0% |
| C | 65% | 0% |
| D | 75% | 0% |
| E | 90% | 88% |
| F | 60% | 0% |

이 수치는 모델이 작성한 대응 정도이며 정확도 평가값은 아니다. 제거 후 B·C·D·F는 검색 단계에서 빈 근거로 제출된 뒤 보고서에서도 모두 「확인 범위 기준 대응 없음」이 됐다. 전후 모두 전제부의 프로세서·컴퓨팅 장치 요건을 별도 대비하지 않았다. 제거 후 보고서의 단락 인용은 ATT-03의 `[0024]`, `[0038]`, `[0042]`, `[0049]`, `[0088]`에 한정됐다.

원시 모델 출력은 각 실행 폴더의 `model_report.md`, 프로토콜 블록을 제거한 읽기용 보고서는 `report.md`, 최종 입력은 `final_prompt.txt`다. 제품의 후처리·DB 저장까지 재실행한 것은 아니며, 검색→동일 최종 분석 호출과 생성된 보고서 본문을 비교했다.

## 판단

**5줄 롤백만으로 품질이 회복된다는 가설은 이번 사례에서 확인되지 않았다.** 이번 제거 후 실행에서는 최종 근거 범위가 오히려 좁아졌다. 다만 각 조건 한 번씩의 실행으로 해당 지시문의 평균적인 유불리까지 단정하지 않는다.

원래 혼잡 실패는 실제 provider 오류였고, 정상 보고서 품질 문제와 구분해야 한다. 오류 분류·재시도·출력 격리를 통째로 되돌릴 근거는 얻지 못했다. 지금은 최소 롤백 상태를 유지하며 제품에 추가 보정 코드를 넣지 않았다. 후속 수정은 기존 검색→최종 선정 경로에서 검토한 원문이 사라지는 지점을 우선 다루고, 단락 파서와 원문 구성 검사도 각각 재현 가능한 사례에 한정하는 것이 타당하다.

실행 중인 운영 서버는 `--reload` 없이 롤백 이전부터 실행 중이다. 소스 변경이 일반 보고서 생성에 적용되려면 PRISM 재시작이 필요하다. 이번 비교는 별도 프로세스에서 수정된 소스를 불러와 수행했다.

## 후속 수정

이후 사용자 요청에 따라 열람 원문을 후속 라운드에 보존하는 경로를 수정했다. 위 표는 수정 이전의 비교 기록으로 유지한다. 실제 전달 손실 재현과 수정 후 보고서 결과는 [열람 근거 보존 검증](reviewed-evidence-retention-2026-09-18.md)에 기록했다.
