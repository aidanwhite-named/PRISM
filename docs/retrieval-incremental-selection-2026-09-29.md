# 구성별 근거 선택 저장으로 반복 입력 줄이기

## 변경 이유

독립된 검색 호출마다 이미 검토한 구성의 열람 원문까지 다시 보내고 있었다.
근거 선택을 끝내도 다른 구성의 조회가 남으면 원문이 계속 입력 예산을 차지했다.
전체 확정 요청은 높은 우선순위의 이월 요청 때문에 거절될 수 있어, 확인을
마친 후보와 남은 검토 범위를 구분한 뒤에도 추가 호출이 생길 수 있었다.

## 현재 흐름

1. AI가 청구항을 구성으로 나누고 문헌별 검색어를 제안한다. 프로그램이 검색한다.
2. AI가 실제 받은 발췌와 필요한 문맥을 검토한다. 완료한 구성의 선택을
   `selected_components`에 반환하고 미확인 구성에만 추가 조회를 요청한다.
3. 프로그램이 구성 ID, 실제 전달된 chunk ID, 원문 위치를 확인하고 선택을 저장한다.
   마지막 회차 전에는 모든 입력 문헌에 대한 검색 이력이 있어야 저장한다.
4. 다음 입력에는 저장한 구성의 ID·구성 설명·근거 수만 남긴다. 미선택 구성의
   검색 기록과 필요한 원문은 유지한다. 전체 청구항과 선행항 문맥도 유지한다.
5. 모든 구성이 선택되면 저장한 선택을 합쳐 기존 근거 패키지와 보고서 작성
   단계로 넘어간다. 전체 근거를 다시 옮겨 적는 별도 확인 호출은 필요 없다.

이는 매 실행을 고정된 두 번 호출로 바꾸는 기능은 아니다. 검색어 수정과
문맥 검토가 필요한 구성은 추가 호출을 사용한다. 기존 `finalize_evidence`
응답도 지원하며, 이때 이미 저장한 구성은 프로그램이 원래 선택 그대로 합친다.

## 검증과 범위 제한

- 선택 저장은 기술적 대응 결론이 아니다. 의미 판단과 보고서 작성은 기존 최종 단계가 한다.
- 실제로 전달하지 않은 원문 ID, 존재하지 않는 ID, 위치 불일치는 거절한다.
- 선택 저장과 같은 구성의 추가 조회를 동시에 요청하면 거절한다.
- 저장된 선택은 다음 모델이 원문 없이 덮어쓸 수 없다. 추가 조회를 명시하면
  해당 구성만 다시 열고 요청한 원문을 반환한다. 다른 구성의 선택은 유지한다.
- 재검토 시 예전 열람 자료 전체를 복원하지 않는다. 요청한 자료부터 예산 안에서
  다시 읽어, 다른 구성의 새 원문으로 채워진 입력이 상한을 넘는 일을 막는다.
- 저장된 구성의 이월 조회는 중지하지만 미처리 기록과 범위 제한 표시는 보존한다.
  미처리 후보를 읽은 것으로 표시하거나, 검색에서 안 나온 것을 문헌에 없다고 확정하지 않는다.
- 여러 구성이 같은 원문을 쓰면 현재 입력에 실제 남아 있는 본문을 기준으로
  참조를 재구성한다. 제외된 구성의 원문을 가리키는 참조를 남기지 않는다.
- 기존 보고서의 출처 검증과 문장 ID 교정은 유지한다.
- 선택·재검토 이력은 검색 trace와 manifest의 `component_selection_events`에 남긴다.

## 확인 방법과 한계

`backend/tests/test_retrieval_selections.py`에서 부분 저장, 자동 완료, 공유 원문의
참조 보존, 미검토 ID 차단, 이월 범위 보존, 마지막 회차 교정, 재검토 예산을 검증한다.
시험용 모델 응답으로 모든 구성의 선택이 끝나면 이월 요청이 있어도 두 번째
호출에서 종료하며 범위 제한은 남는 것을 확인한다. 이는 실제 보고서가 항상
두 번에 끝난다는 의미가 아니다.

실제 모델로 보고서를 재생성하지 않았다. 입력 축소와 호출 종료 조건은 검증했지만
전체 토큰 절감률과 보고서 품질 변화는 다음 실제 실행의 사용량·근거를 비교해야 한다.
기존 보고서와 실행 기록은 수정하지 않는다.
