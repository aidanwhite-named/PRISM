# 보고서 보완 근거 연결 형식 복구

대상 작업은 `4841bc99-43f7-4862-ba33-2e38505d6535`이며, 실행 자료는
`ce933ea1-9cca-4180-8bf8-2caf63f6e7ba` 폴더에 저장되어 있다.

## 원인과 수정

- 모델이 `supplements.evidence`에 배열 대신 단일 문자열 `E8`을 반환했다. 정확한 단일 E번호는 목록으로 읽도록 호환 처리했다. 존재 여부, 해당 문헌 소속, 차이 해소 항목과의 연결 및 원문 검증은 그대로 수행한다. 쉼표로 연결된 문자열·없는 근거·다른 문헌의 근거는 통과시키지 않는다.
- 형식 검증 실패 시 보완 설명까지 버려져 ‘보완 방법 누락’ 경고가 연쇄적으로 발생했다. 문헌 자체가 유효하면 작성된 설명은 ‘근거 연결 확인 필요’로 보존하되, 잘못 연결된 발췌를 검증된 인용처럼 표시하지 않는다.
- `supported`와 잔존 차이 칸의 ‘실질적 기술 구성상의 차이는 해소됩니다.’가 충돌로 처리됐다. 독립된 명확한 무차이 선언만 제한적으로 인식한다. 부정·조건·추가 문장·구체적인 잔존 차이가 있으면 기존 점검을 유지한다. 원래 문장과 모델 판단은 바꾸지 않는다.
- 모델 출력 지침에도 단일 근거의 배열 형식과, `supported`일 때 잔존 차이를 빈 문자열로 작성하는 규칙을 명시했다.

## 검증과 복구

- 구조화 보고서·문장 교정·원문 전달·내장 지침 관련 172개 테스트 통과.
- 실제 저장 응답을 원문으로 재검증: 원문 근거 8개 모두 유효, 점검 오류 3개 → 0개.
- 문헌 매핑, 원문 발췌, 번역, 구성별 점수와 분석·판단 데이터가 이전과 동일함을 확인했다.
- 추가 모델 호출 없이 인용발명 2의 발췌와 보완 설명을 복원했다.
- 원래 보고서 파일과 변경 대상 DB 필드는 실행 폴더의 `report-link-recovery-20260930/original`에 백업했다. 원 모델 응답은 변경하지 않았다.
- 앱의 DB 결과와 다운로드 파일을 갱신한 뒤 실제 API 응답에서도 경고 제거와 보완 설명 복구를 확인했다.
- 실행 중인 서버 재시작은 도구 정책으로 차단되었다. 이후 생성분에 코드 변경을 적용하려면 프로그램을 재시작해야 한다.
