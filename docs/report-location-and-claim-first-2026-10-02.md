# 문헌 위치 표시와 청구항 기준 대응 이유 수정

## 확인한 원인

- 대상 실행: `4dbc8810-cf59-4c7c-83d9-87ec38ffce89`.
- 주 인용발명은 `Air Meshes for Robust Collision Handling` (`ATT-03`). E1과 E2의 원문 문장 ID 및 검증된 페이지는 모두 PDF 4페이지다.
- 기존 표시 코드는 발췌 앞에 있는 대괄호 안의 4~6자리 숫자를 단락 번호로 간주했다. PDF 4페이지의 `Agarwal et al. [2000]`에 있는 발표 연도를 직전 단락 번호로 잘못 사용했다. 원문 선택·페이지 검증이 아니라 보고서의 위치 표시 단계에서 발생한 오류다.
- 기존 reasoning은 인용발명 내용을 먼저 설명하고 마지막에 청구항 대응을 설명하는 형태였다. 생성 지침의 비교 대상은 청구항이었지만, 서술 방향과 JSON 예시가 청구항을 먼저 제시하도록 명확하게 제한하지 않았다.

## 수정

- 위치 표시에서는 줄 시작의 구조적 단락 표식을 확인한다. 일반적인 0 패딩 단락 번호는 인정하고, 패딩이 없는 번호는 연속 번호 구조가 확인될 때만 인정한다. 단독으로 줄바꿈된 `[2000]`도 발표 연도를 단락 번호로 바꿀 근거로 삼지 않는다. 불확실하면 검증된 PDF 페이지를 표시한다.
- 원문 발췌에서 제거하는 번호는 원문 위치로 확인한 단락 표식만으로 제한한다. 단락 번호와 같은 숫자의 본문 인용 연도도 원문·번역에서 보존한다. 원문 문장 ID 생성 규칙은 변경하지 않았다.
- 기존 보고서의 두 위치를 `PDF 페이지 4`로 정정했다. 정정 전 파일과 DB 표시 내용을 실행 폴더의 `location-correction-20261002-085807`에 백업했다. DB `result_text`와 `result.md`만 고쳤으며, 청구항·유사도·원문·번역·대응 판단·기존 reasoning은 유지했다. 실행 중인 API가 정정된 보고서를 반환함을 확인했다.
- 생성·발췌 연결 보완·의미 검토·의미 교정에 공유되는 지침과 기본 프롬프트를 청구항 기준으로 변경했다. reasoning은 청구항의 대상·동작·조건·관계 순서대로 각 요구 사항을 먼저 제시하고, 인용발명 1의 대응 내용 또는 확인되지 않는 한정을 설명한다. 필요한 보완 문헌도 청구항의 미대응 한정에서 출발하여 연결한다.
- 독립 검토에서도 인용발명 요약으로 시작하는 설명이나 청구항 한정의 대응 여부가 빠진 설명을 교정 대상으로 삼는다. 서술 순서만 교정할 때 근거·점수·기술적 판단을 변경하지 않도록 명시했다.

## 검증과 적용 범위

- 관련 9개 테스트 모듈 **289개 통과**: 보고서 컴파일, 공유 지침, 문헌별·의미 검토, 연결 보완, 원문 전달, 기본 지침, 프롬프트 조립, 문장 선택, 발췌 보완.
- 발표 연도 전후 발췌, 줄바꿈된 연도, 발췌 안의 연도 보존, 실제 특허 단락, 실제 `[1999]`~`[2001]` 단락 번호 구조, 원문·번역에 같은 숫자가 있을 때 보존, V5 문장 ID 선택, 전체 원문 및 검색 발췌 경로를 확인했다.
- 실제 기존 V5 보고서를 정정된 컴파일러로 재출력하여 두 위치 외에는 동일하고, 특허 문헌의 `[0052]`, `[0053]`, `[0057]` 표시도 유지됨을 확인했다. 기존 검토 미완료 안내는 보존했다.
- 현재 보고서의 위치 정정은 화면 새로고침으로 확인할 수 있다. 새 위치 판정 및 청구항 기준 작성 지침은 실행 중인 백엔드를 재실행한 뒤 새 보고서 생성·수정에 적용된다. 기존 reasoning을 새 모델로 재작성하는 작업은 수행하지 않았다.
