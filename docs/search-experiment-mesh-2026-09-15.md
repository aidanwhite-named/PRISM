# 메시 병합 청구항 직접 검색과 PRISM 반영

## 범위와 판정

2026-09-15, 저장 실행 `8cd0e1cc-6c09-4124-b43c-f899eed81d08`의 청구항을 대상으로
웹 검색과 문헌 본문 열람을 수행했다. 검색 기준일은 원래 실행과 같이 지정하지 않았다.
이번 직접 검색은 PRISM의 Codex CLI/EPO/OpenAlex 실행과 동일한 도구 조건의 A/B 실험이 아니다.
아래 대응 평가는 기술적 검토 의견이며 신규성·진보성 판단이나 전체 검색의 충분성 인증이 아니다.

기존 B 두 건으로는 확인되지 않았던 구체적 기술 관계가 다른 문헌에 존재한다.
따라서 기존 결과를 대응 문헌 부재로 읽는 것은 부적절하다. 다만 단일 문헌에서
청구항 A~F 전부의 동일한 관계를 확인한 것은 아니다.

## 실제 검색의 진행

1. 청구항을 (A) 복수 메시·변환·외관 입력, (B) 로컬→월드 좌표,
   (C) 정점 배열 결합과 인덱스 오프셋, (D~E) 아틀라스 영역과 UV 조정,
   (F) 단일 메시 출력으로 나누었다.
2. 전체 단어를 모두 AND로 묶지 않고 관계별로 검색했다.
   - `patent "mesh" "world coordinate" "texture atlas"`
   - `patent "merging" "meshes" "index" "offset"`
   - 기존 실패 후보 번호를 확인하고 전용 페이지를 열었다.
3. 병합의 구현 용어와 목적을 넓혔다.
   - `patent "mesh merging" "texture atlas"`
   - `patent "static batching" texture coordinates`
   - `"Multiple sub-meshes encoding" patent`
   - `"mesh" "atlas" "G06T15/04" "merge"`
   마지막 질의의 분류코드는 US9626789B2 페이지에서 확인했다. 이 웹 질의는
   EPO 구조화 CPC 검색을 실행한 것과 같지 않다. 분류 결합의 독립적 개선 효과도 측정하지 않았다.
4. 결과 제목이 가까운 것만 세지 않고 본문의 알고리즘·청구항·그림 설명을 확인했다.
   EP4643310A4는 본문이 빈약해 같은 패밀리의 US20240212218A1을 확인했다.
   패밀리 연결은 EP 페이지에 표시된 국가별 링크를 사용했다.
5. `static geometry batching`으로 이어진 학위논문의 3.10.5절을 읽고,
   그 절이 가리킨 GPU Gems 2 Chapter 3를 NVIDIA 원문에서 확인했다.
   DOI 검색에만 의존했으면 놓칠 수 있는 저자 공개 학위논문과 기술서다.

## 일반화해 반영한 동작

- 기본 전략: 핵심 관계별 짧은 질의와 전체 흐름 질의를 병행하고, 원문 용어·분류·
  참고문헌에서 확장한다. 잡음이 계속되는 논문 질의는 제목·초록 및 다른 출처로 전환한다.
- 런타임 계약: 종료 이유, 확장 결과, 넓은 페이지 표본의 보완 내역, 남은 관계를
  `search_review`로 보고한다. 조회 실패 후보는 미확인으로 남기고, 제외·통합에는
  `candidate_dispositions`의 식별정보와 이유를 요구한다.
- EPO 도구: `begin`으로 페이지 이동 가능(1~2000). 전달 범위, 다음 위치,
  반환 문헌 날짜 범위를 제공한다. 전체 결과가 페이지 크기의 10배를 넘으면
  `broad_query_sample` 경고를 제공한다. 10배는 표본 경고 기준이며 검색 충분성 기준이 아니다.
  EPO의 전체 결과 조회 상한은 [공식 OPS 문서](https://link.epo.org/web/searching-for-patents/data/en-ops-v3.2-documentation-version-1.3.20.pdf)에 따른다.
- 오류 응답: 원래 fault를 보존하면서 미지원 constituent/EntityNotFound의 대체 조회
  방법을 journal과 MCP 응답에 함께 제공한다. 실패를 조회 성공으로 바꾸지 않는다.
- 종료 감사: 실제 상세 조회한 식별자를 최종 후보·제외 기록·기준일 제외 기록과
  대조한다. 누락되면 화면과 Markdown 보고서에 노출한다. 넓은 EPO 응답이 있는데
  표본 보완 기록이 없거나 종료/확장 이유가 없으면 감사 미완료로 표시한다.
- 근거 검증이 완료돼도 종료 감사가 미완료면 manifest는 `search_incomplete`가 된다.
  검증 자체도 미완료면 기존 `verification_incomplete`를 유지하고 별도로 감사 상태를 표시한다.
- DOI 없는 학위논문을 유지할 수 있도록 공식 후처리가 빈 문헌번호로 EPO를 조회하지 않는다.

후보의 기술적 분류·순위는 모델이 맡는다. 코드가 강제로 문헌을 추가하거나 이 실험의
번호·검색어를 실행 경로에 넣지는 않았다. 발견한 모든 검색 결과의 누락을 감지하는 것은
아니며, 현재 기계 대조의 범위는 실제 상세 조회한 단서다. 모델이 적은 종료 이유의
기술적 타당성을 코드가 인증하지도 않는다. 무조건 호출 한도를 채우는 정책이나
자동 반복 검색 루프는 추가하지 않았다.

## 검증과 한계

회귀검증은 페이지 위치의 HTTP 요청 전달, 2000건 경계, 광범위 응답 경고,
실패 후보의 무기록 소실, 중복 관측, 기준일 제외, DOI 없는 원문,
종료 기록 파싱, 오류 복구 안내와 화면 표시를 대상으로 한다.

저장 실행의 후보와 로그를 새 감사기로 재평가해 US 세 건의 미기록 소실을 탐지한다.
원래 실행 파일이나 DB 결과는 고쳐 쓰지 않는다. 이 실험은 새 전략으로 동일 모델을
재실행했을 때의 재현율·시간·비용 개선을 측정한 것이 아니다.

실제 재평가 결과: `unaccounted_fetches`는 US20200357176A1, US9536343B2,
US9626789B2의 세 건이다. 광범위 표본은 전체 787·462·51,567건의 세 응답이며,
종료 이유·확장 결과·페이지 편향 보완 기록이 모두 누락된 것으로 표시됐다.
기존 최종 후보 수는 2건 그대로다.

관련 백엔드 회귀 테스트 두 묶음(185건 및 190건, 중복 포함)이 통과했다.
화면 렌더링 테스트 12건 및 TypeScript/Vite 빌드도 통과했다.
