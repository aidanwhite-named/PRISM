# 검색 결과에서 구성대비까지

검색은 후보 발견과 잠정 선별을 담당하고, 기존 구성대비 엔진이 실제 본문의 구성별 근거와 위치를 분석한다. 검색 중 본문을 읽었다는 상태는 구성대비 완료를 뜻하지 않는다.

## 사용 흐름

1. 검색 결과에서 문헌을 선택한다. 우선 검토 후보 최대 3건을 선택하는 편의 버튼이 있으며, 한 번의 분석은 최대 5건이다. 이는 비용 관리 한도이지 관련성 판정 기준이 아니다. 보류·낮은 관련성 후보도 직접 선택할 수 있다.
2. 프로그램이 모델 호출 없이 원문을 확보한다. 검색 도구가 보존한 원본 응답이 있으면 재사용한다. 잘린 검색 발췌문은 분석 자료로 승격하지 않는다.
3. 확보한 자료를 CITATION 첨부로 정규화하고 기존 분석 작업 생성·실행 경로로 전달한다. 검색 당시의 청구항과 출원 명세서는 이어받고, 검색 요약과 순위는 대응 근거로 전달하지 않는다.
4. 구성대비 설정의 모델로 분석한다. 검색 화면에서 실제 자식 작업의 상태를 조회하고 분석 화면으로 이동할 수 있다. 작업 성공은 모든 구성이 대응한다는 뜻이 아니다.

## 원문 범위

- Google Patents: 공개번호가 일치하는 설명·청구항 텍스트. 도면은 포함하지 않는다.
- 공개 PDF: 직접 PDF 또는 페이지의 `citation_pdf_url`로 명시된 논문 PDF. 텍스트와 페이지 위치를 기존 추출기로 보존한다. PDF의 존재만으로 문헌 완전성이나 동일성이 검증된 것은 아니므로 분석 지침에서 확인하도록 한다.
- 초록·서지 페이지, 접근 제한, 스캔 PDF 등은 사유와 함께 보류한다. 일부 문헌만 확보되면 확보한 문헌만 분석한다. 사용자 원문 PDF 첨부는 기존 구성대비 화면에서 가능하다.

## 구현과 실행 보장

`POST /api/jobs/{search_id}/comparisons`는 `candidate_ids`를 받는다. 서버는 검색 종료, 후보 소속, 기준일 및 최대 개수를 검증한다. 같은 선택의 기존 분석 작업이 있으면 해당 작업을 반환한다. 한 프로세스로 실행되는 데스크톱 서버에서 검색별 비동기 잠금으로 중복 실행을 방지한다. 다중 worker 배포 시에는 DB 수준의 고유 실행키가 필요하다.

원문 확보는 두 건씩 병렬로 수행하며 기존 HTTPS 주소 검증과 다운로드 제한을 적용한다. 준비 중 화면을 떠나도 서버 요청이 이미 수락되었다면 분석이 생성될 수 있다. 실행된 분석의 취소는 기존 분석 화면에서 한다.

부모 `search_manifest.comparisons`에 선택 문헌, 확보/보류 내역, 자식 작업 ID를 저장한다. 자식 작업과 연결은 같은 트랜잭션으로 저장한 다음 runner에 제출한다. `GET /api/jobs/{search_id}/comparisons`는 현재 분석 상태를 반환한다. 원문은 자식 폴더에 복사되어 원래 검색을 삭제해도 분석 자료는 유지된다.

이 변경은 사용자가 선택한 후보를 실제 분석으로 연결한다. 검색 종료 후 모든 후보를 자동 분석하지 않는다. 토큰 절감률은 실문헌과 모델을 고정한 별도 비교 실험이 필요하다.
