# Kiwee 서버 시험 연동

환경 설정 → **Kiwee 검색 (시험 연동)** 에서 `Kiwee 연동 사용`을 체크하고
**Kiwee 설정 저장** → **Kiwee 시험 검색** 순서로 실행한다. 기본 검색어는 `반도체`이며
5건씩 조회한다. 시험 검색은 AI 사용량 없이 요청·인증·응답 형식을 확인한다.

기본 주소는 설치된 `C:\KIPRO\NK\Services.dll`의 SolrService에서 확인한
`https://gateway.kiwee.or.kr/solr/select`, 국내 범위는 `shd_kr`다.
`Files/FIELDS.html`에는 제목 `tl`, 초록 `ab`, 청구항 `cl` 검색 항목이 있다.
서버의 현재 필드와 호환되는지는 실제 인증된 검색으로 검증해야 한다.
공백으로 나눈 각 키워드를 제목·초록·청구항 중 하나에서 찾도록 AND로 조합한다.
Solr 직접 입력 모드는 Kiwee 화면의 검색식 변환기를 재현하지 않는다.

활성화하면 기존 검색 MCP에 `kiwee_search`가 추가된다. 청구항 분석과 검색식 선택은
기존 검색 AI가 수행한다. 서지·반환 텍스트는 기존 근거 저장소에 보존한다.
원문성, 원문 언어, 번역 여부는 미확인이므로 공식 원문 등급을 부여하지 않는다.
공개번호를 확정할 수 없는 결과는 자동 후보 등록에서 제외하고 시험 화면에서는
내부 ID와 반환 필드 등을 확인할 수 있게 한다. 없는 청구항·본문을 생성하지 않는다.

## 인증과 현재 실측

2026-10-07 이 PC에서 기본 서버에 시험 접속했을 때 Windows Schannel이
`SEC_E_UNTRUSTED_ROOT`를 반환했다. 실제 특허 검색 성공이나 Kiwee UI 결과와의
동등성은 확인되지 않았다. 먼저 기관 CA 신뢰를 설정해야 하며 이후 클라이언트
인증서·계정 권한이 추가로 필요할 수 있다. 프로그램의 Common.dll에는 클라이언트
인증서를 사용하는 통신 코드가 있다. 로그인 세션·비밀번호·개인 키를 자동 추출하지 않는다.

- CA 오류: 기관에서 제공한 루트 인증서를 Windows에 설치하거나 고급 설정의
  CA 파일에 PEM 경로를 지정한다. 인증서 검증을 끄는 옵션은 없다.
- 클라이언트 인증: Windows 현재 사용자 → 개인 저장소에 있는 유효한 인증서의
  SHA-1 지문을 지정한다. 개인 키는 저장소에 남고 Schannel이 사용한다.
- HTTP 401/403: 인증 또는 검색 권한 요구. 담당자에게 확인한다.
- HTTP 400: 전송 검색식·범위·필드 호환성을 확인한다.
- HTML/로그인 페이지/부분 응답: 성공 0건으로 처리하지 않고 오류로 표시한다.

Windows는 OS의 curl/Schannel, 다른 OS는 Python HTTPS를 사용한다.
클라이언트 인증서 지문 기능은 Windows 전용이다. 요청은 검증된 HTTPS `/select`에
고정된 읽기 검색 매개변수만 보낸다. 리디렉션을 따라가지 않으며 결과는 최대 50건,
응답은 8MB, 연결 대기는 25초로 제한한다.

## 검증

Kiwee 어댑터·시험 API·MCP 등록·인증 실패·응답 검증·근거 재추출 테스트와
검색 정책·허용 도구·Provider 스트림·보안 관련 회귀 검사를 통과했다.
프론트엔드의 Kiwee 및 환경 설정 화면 테스트 23건, 타입 검사와 배포 빌드도 통과했다.
재시작한 로컬 PRISM의 실제 `/api/kiwee/search`에서도 `KIWEE.TLS`,
`ok=false`, `total_found=null` 응답을 확인했다.

별도의 `test_search_api.py` 실행에서는 기존 보완검색 완료 조건 테스트
`test_gap_search_uses_selected_components_in_combined_then_individual_order`가 실패했다.
이번 Kiwee 변경만 되돌린 격리 사본에서도 동일한 실패를 재현했다.
