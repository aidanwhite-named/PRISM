# 페이지 열람 진행과 근거 공유 — 2026-09-05

## 수정

구성 몫을 요청 수로 쪼개는 방식은 실제 PDF 한 페이지도 못 담는 배분을 만들었다.
구성별 고정 잔액과 최소/예약 몫을 제거했다. 먼저 요청된 문맥 열람을 처리하고,
읽기·검색 각 단계에서 구성마다 한 요청씩 순환한다. 읽기는 전체 잔여 공간에서
페이지 전문을 담고, 검색은 아직 처리할 구성 수로 잔여 공간을 나누어 받는다.
정확히 같은 바이트 수를 보장하는 배분이 아니라 요청의 실제 진행을 보장하는 순서다.
페이지 하나가 전체 라운드 예산보다 크면 여전히 미완료로 남긴다.

동일 자료·chunk_id·원문·앞뒤 문맥은 최종 모델 입력에서 한 번만 싣는다.
반복 위치에는 자료 번호·chunk_id 참조와 구성별 관련성 메모를 남긴다.
근거 패키지 JSON에는 모든 구성의 원문과 출처가 그대로 있고, 렌더링할 때만
공유한다. 렌더링마다 공유 집합을 새로 만들므로 다른 호출의 기억을 가정하지 않는다.
동일 chunk_id라도 자료나 문맥이 다르면 공유하지 않는다. 예산 축소로 첫 근거가
제거돼도 다음 렌더링에서 남은 근거가 원문을 제공한다.

페이지 본문과 발췌문 사이의 부분 중첩 제거까지 새로 구현하지는 않았다.
이번에는 동일 근거의 구성 간 반복만 제거해 기존 페이지 확장에 공간을 확보했다.
