# 프로그램이 조립하는 구성대비 보고서

## 현재 계약: V5 (2026-10-01)

새 분석은 V5를 사용한다. 한 구성의 evidence/reasoning에 복수 인용발명을 허용하며 문헌별 실제 대응 한정을 설명한다. 유사도는 인용발명 1 기준으로 유지하므로 다른 문헌의 대응을 점수에 합산하지 않는다. `difference`는 복수 문헌으로도 대응되지 않는 한정·관계만 구성별 한 문장으로 기록하며, 없으면 빈 문자열이다. 낮은 주 문헌 점수만으로 차이점을 요구하지 않는다. 신규 응답에는 `resolution`, `supplements`, `derivation`을 작성하지 않는다.

`evidence_uses`는 각 구성에 연결한 모든 발췌 ID를 `support`(해당 한정의 실제 대응) 또는 `contrast`(문헌의 다른 처리 방식을 보여 주는 비교 설명)로 구분한다. 모든 발췌를 reasoning의 `{{E1}}` 참조와 연결한다. 일반 배경은 제외한다. `support` 문헌은 연결된 근거에서 프로그램이 산출하며, 모델이 별도 긍정 역할을 중복 작성하지 않는다. 비교 설명용 발췌만 사용하는 문헌은 `comparison`으로 산출하며, 이 인용만으로 문헌 전체 미발견을 추정하지 않는다. `reference_roles`에는 명시적으로 판단한 `not_found`/`unavailable`만 기록한다. `not_found`와 비교 설명용 발췌는 공존할 수 있으나, 비교 발췌만으로 주 문헌의 양수 점수를 뒷받침할 수 없다. `unavailable` 문헌에 발췌를 연결하거나 실제 대응 근거와 `not_found`를 혼용하면 점검 대상으로 남긴다. V1–V4 저장 결과는 기존 해석으로 읽고, 재검토에서 명시적으로 용도를 추가한 구성만 새 구분을 적용한다.

구성 교정은 영향을 받은 구성의 관련 문헌에 대해 원래 전달된 원문·문장 번호를 다시 제공한다. 검색 전달은 제공된 검색 구간에 한정한다. 기존 발췌·번역·문헌 매핑·청구항 문언은 보존하며, 누락된 실제 대응 근거는 제공 문장 번호에서 새 ID로 선택할 수 있다. 재검토 원문을 제공하지 않은 문헌에 새 미발견 판단을 만들 수 없다. 새 발췌는 동일 문헌·페이지의 연속 문장과 번역을 검증하고, 선택한 구성의 설명과 연결된 경우에만 반영한다. 입력·시간 한도 또는 재검토 실패 시 기존 결과와 점검 항목을 보존한다.

문헌별 근거·번역 검증은 유지한다. 같은 문헌·페이지·원문의 발췌는 보고서에서 처음에만 출력하고 이후에는 앞의 구성과 근거 번호를 참조한다. 외국어 문헌은 필요한 선택 범위를 전체 번역하되, 위치 뒤 원문은 최대 120자의 연속 구절과 생략부호로 표시한다. 전체 원문과 번역은 감사 데이터에 보존한다. 한국어 문헌 발췌에는 이 표시 길이 제한을 적용하지 않는다.

근거 추가는 새로운 필수 한정·관계 또는 필요한 문맥을 입증할 때만 허용하도록 지시한다. 같은 사실의 개요·실시예 반복, 주변 장치·일반 배경·절 제목·도면 소개는 제외한다. 원문 일치 검증은 기술적 대응의 타당성이나 의미상의 중복 여부를 자동 보증하지 않는다.

V5도 기존 문장 선택·분할 복구를 사용하며 분할된 근거마다 구성별 용도를 보존한다. 저장된 V1–V4 결과는 당시 계약으로 재현할 수 있으며 기존 분석과 점수를 자동으로 재작성하지 않는다. 아래 내용은 이전 계약의 변경 이력이다.

## V4 변경 이력

V4 구성 정합성 보완: 비어 있는 기호는 사용자 기호와 충돌하지 않는 `(자동 구분 N)`으로 표시하며 원 응답은 변경하지 않는다. reasoning에 명시된 검증된 E번호는 누락된 구성별 evidence 연결을 복원하고 기록한다. 문헌 이름만으로는 근거를 추정하지 않는다. `not_found`인 주 문헌의 점수는 0, `unavailable`은 null이어야 한다.

문장 선택 복구 후에도 구성의 근거 연결·문헌 역할·점수 불일치가 남으면 검증된 전체 발췌 목록으로 해당 구성만 1회·최대 120초 재검토한다. 청구항 문언·기호·문헌 매핑·근거 원문·번역은 수정할 수 없다. 새 근거 및 발췌 목록만으로 내리는 새로운 문헌 전체 미발견 판단은 거절한다. 컴파일 검증을 다시 통과한 구성만 반영하며 실패·취소·한도 초과에서는 원 결과와 점검 표시를 유지한다. `component-repair`에 입력·응답·교정본·감사를 저장하고 사용량을 `component_repair`로 별도 집계한다. 이는 근거 연결과 점수 기준의 재검토이며 의미적 정확성의 보증은 아니다.

2026-10-01: `difference` 누락·형식 오류도 구성별 점검 상태와 재검토 대상에 포함한다. 이전에는 보고서 전체 점검 목록에만 추가되어 자동 복구가 해당 구성을 놓쳤다. 차이점만 누락된 구성은 `difference_only` 범위로 검토하고 `component_index/difference/review_basis`만 받는다. 다른 점수·근거·설명은 보존한다. 빈 문자열은 검토 후 잔존 차이가 없음을 뜻하며 항목 자체가 빠진 것과 구분한다. 이유 없이 모두 빈 값으로 채우는 지시는 사용하지 않는다.

## 이전 계약과 변경 이력

2026-09-29 출력 보완: 구성 제목 아래에 청구항 문언을, 발췌 뒤에는 대응 이유를 표시한다. 단락번호는 위치에 모아 표시하고 검증용 원문은 보존한다. 95점 미만의 점수에 구체적인 차이 설명이 없으면 ‘차이점 없음’ 대신 재확인 안내를 표시한다. 페이지 말미의 미완성 열거 항목에는 번역 범위 확인 안내를 붙인다. 점수와 기술적 차이를 프로그램이 임의로 변경하지 않는다. 재현 기록은 `report-output-review-2026-09-29.md`를 참조한다.

일반 분석 프롬프트에는 단일 구조화 결과 규격을 붙인다. 기본 분석 프롬프트에서 Markdown 표·문단 서식 지시를 제거했고, 모델은 documents/evidence/components/summary를 한 번만 출력한다. 기존 기계용 블록을 명시적으로 포함한 사용자 프롬프트는 호환 모드를 유지한다.

프로그램은 문헌 순서에서 인용번호를 부여하고, 기존 고정 매핑이 있으면 그 번호를 보존한다. 각 근거는 실제 ATT-자료와 연결하며, 본문 서술의 {{ATT-01}} 참조도 번호로 치환한다. 출원 명세서를 인용발명으로 등록할 수 없다.

근거는 E번호로 한 번 기록하고 여러 구성에서 참조한다. 새 응답 계약은 version 3이며, 전체 문헌에는 `ATT-01-P3-T2`, 검색 구간에는 `S001-T2` 형식의 문장 번호를 실제 원문 앞에 표시한다. 모델은 `sentence_ids`와 선택 범위 전체의 `translation`만 반환하며 `quote`를 다시 쓰지 않는다. 프로그램은 동일 문헌·페이지·원문 묶음 안에서 연속된 번호인지 검사한 뒤 실제 텍스트를 잘라 원문과 위치를 복원한다. 떨어진 문장·다른 페이지는 각각 별도 E번호와 번역으로 선택해야 한다. 모르는 번호, 다른 문헌의 번호, 건너뛴 번호, 중복·역순 선택과 모델이 다시 쓴 quote는 오류로 표시한다. 문장 분할은 약어·OCR로 인한 조각을 포함할 수 있어, 이어지는 번호를 함께 선택하여 완결된 문맥을 보존한다. 번역과 기술적 대응의 정확성은 모델의 판단 영역이며 이 검사로 보증하지 않는다. 유사도·결론과 보고서 출력 양식은 바꾸지 않는다.

이전 version 1/2의 S번호·문자 범위와 직접 quote 응답은 호환한다. 직접 발췌는 공백을 제외한 문자 일치를 검사한다. 지정 페이지에서 일치하지 않으면 전달된 범위 안의 다른 페이지를 검색하며, 일치 페이지가 하나뿐일 때만 위치를 정정하고 기록한다. 대소문자·문장부호·어순 변경, 중간 생략은 유사 일치로 통과시키지 않는다. 검색 실행은 빈 패키지를 포함하여 전달된 원문 밖으로 검증 범위를 넓히지 않는다. 저장 보고서는 변경하지 않는다.

번호, 문헌 표, 구성별 제목, 점수에 따른 등급, ASCII 큰따옴표와 종합 요약 제목을 프로그램이 생성한다. 청구항별 `[구성요소]` 아래 `(A) 실질적 동일 🟢 (85%)`처럼 구성 기호·등급·기존 심볼·점수를 출력하고 다음 문단에 근거를 표시한다. 점수 구간은 그대로이며 등급명은 동일/실질적 동일/일부 차이/대응 없음이다. 외국어는 `"번역문" (위치; "원문 발췌")`, 한글은 `"발췌문" (위치)` 순이다. 확인된 원문 문맥에 단락 번호가 있으면 이를 사용하고, 없으면 복원한 PDF 페이지를 사용한다. 위치를 모르면 페이지를 만들지 않는다. 발췌의 문자 일치는 기술적 대응이나 번역의 정확성을 보증하지 않으며 이 판단은 모델의 책임으로 구분한다.

번역 누락·없는 근거·불일치 발췌는 근거 번호와 문헌을 특정하여 해당 위치와 항목 점검에 표시한다. 원문과 맞지 않는 문장을 직접 인용처럼 보여주지 않는다. 대응 이유에 사용한 문헌의 검증된 발췌·번역이 없으면 대응 판단에도 확인 필요를 표시한다. JSON 자체가 깨졌거나 문헌 매핑이 모호하면 형식 오류로 종료하며 원 응답을 보존한다.

V3 문장 선택 검증에 실패한 경우에만 이미 전달된 해당 문헌 원문과 실제 문장 번호로 재선택을 요청한다. 최대 2회·총 180초(실행 제한 시간이 더 짧으면 그 시간)이며, 입력 문자·Provider 바이트·모델 토큰 한도를 다시 적용한다. 기존 문헌 매핑·구성·점수·판단과 정상 근거는 변경하지 않는다. 검증을 통과한 문장 선택과 번역만 항목별로 반영하고, 실패한 항목은 보고서 상단에 근거 확인 미완료로 표시한다. 번역의 의미적 정확성이나 대응 판단 자체를 보증하는 기능은 아니다.

원 응답은 analysis-response.txt에 보존한다. 재선택의 입력·응답·검증 기록과 채택된 분석 JSON은 작업 폴더 sentence-repair에 별도로 저장한다. 추가 사용량은 총계에 합산하고 sentence_repair로 분리해 기록한다. 취소·호출 실패·시간/입력 한도에서는 확인 가능한 기존 결과를 보존한다. 지침의 문장 번호 예시도 전체 전달과 검색 전달 중 실제 선택된 방식만 사용한다.

차이 해소 검토의 `resolution`은 `{gap, evidence, explanation, remaining_difference, conclusion}` 객체다. 해소 판단은 `supported`, `remaining_gap`, `insufficient` 중 하나이며, 차이가 없으면 null이다. 프로그램은 구성대비 evidence와 차이점 resolution.evidence를 각각 검증하며 자동으로 합치지 않는다. 다른 구성이나 문헌에서 근거를 추정해 가져오지는 않는다. 구성대비 뒤의 `[차이점]`에 `구성 (N)에 대해`로 시작하는 문단을 출력한다. gap은 주 문헌의 부족한 한정을 특정하고 explanation의 `{{E1}}`을 검증된 번역·위치·발췌로 치환한다. 근거 ID는 해당 검토의 근거 목록에 연결되어 있어야 한다. 이전 응답처럼 문장 내 참조가 없으면 연결된 근거를 문단 안에 별도로 보존한다.

서술 경로는 (1) 다른 문헌의 구체적인 근거와 대응 이유·보완 범위, (2) 가장 가까운 실제 근거의 제한된 대응 범위와 끝내 남는 차이, (3) 필요한 주지관용·설계변경의 방법·기술적 이유와 해소 가능 여부 또는 한계다. 모델의 검토는 허용하되 보고서 분석 서술은 구성대비·유사점·차이점으로 한정한다. 결합 동기·양립 가능성·결합 후 도출 용이성을 별도 항목으로 요구하지 않으며, 법적 최종 결론을 출력하지 않는다. 일부 대응을 전체 해소로 확대하지 않는다. 근거를 찾지 못해 evidence가 비어 있는 insufficient는 그 자체로 연결 오류가 아니며, 부족한 근거와 잔존 차이를 기록해야 한다. 근거 없는 supported는 연결 오류를 표시하되 내부 상태는 보존한다. 구성 원문과 대응 이유는 구조화 결과에 보존한다.

누락·검증 실패·번역 누락·설명에만 등장한 문헌·모순된 해소 상태는 `resolution_checks.status=needs_review`로 남긴다. 모델의 상태 판단은 `model_conclusion`에 내부 검증용으로 보존하지만 보고서에 별도의 `해소 판단(모델 분석)` 문구를 붙이지 않는다. 점검은 근거·항목 연결 상태이며 기술적 판단을 변경하지 않는다. 결론 자체가 없는 이전 자유서술 응답에는 결론을 만들어 넣지 않는다. 발췌·번역·위치 순서와 기존 저장 보고서는 변경하지 않는다.

구성대비에서 주 인용발명 외의 근거를 프로그램이 제외한다. 다른 문헌이 대응 이유 또는 근거에 혼입되면 `comparison_checks`에 제외 근거와 확인 필요 상태를 기록하되, 모델이 반환한 유효한 점수는 출력·분석 manifest에 그대로 보존한다. 차이점에는 `resolution.evidence`만 사용하며 구성대비 근거를 자동 합산하지 않는다. 선택 구간 경계를 넘는 인용은 같은 전달 페이지의 선택 구간 안에서 시작하는 유일한 연속 원문일 때 복원한다. 잘린 미리보기가 quote로 복사되지 않도록 선택 색인에는 ID·문자 범위만 표시한다.

기존 형식으로 응답한 제공자는 이전 파서로 처리하되 자동 조립되지 않았다는 안내를 표시한다. 기존 저장 보고서는 변환하지 않는다.

새 보고서는 기존 analysis_manifest에 report 필드로 구조화 결과·검증 근거·점검 항목을 저장하며, 작업 폴더에 structured-report.json과 analysis-response.txt를 추가한다. 화면·복사·다운로드는 동일한 result.md를 사용한다. DB 마이그레이션이나 별도의 검토 모델은 필요하지 않다. 구성별 자동 재질의 기능은 이번 변경에 포함하지 않으며, 비용 실측도 수행하지 않는다.


## 내장 지침 관리

출력 가독성: 각 청구항의 `[차이점]` 앞에는 Markdown 구분선을 출력한다. 차이점의 문헌 참조는 새 문단에서 시작하고, 보완 문헌의 발췌와 explanation은 `라는 기재가 있으며,`로 연결한다. explanation은 하나의 완결된 문장으로 작성하도록 지시하되 인용문·번역의 문장부호는 수정하지 않는다. gap/remaining_difference에서 주 문헌을 부족한 한정의 대상으로 언급한 것만으로는 발췌 연결 누락을 경고하지 않는다. 실제 근거 설명과 연결된 근거의 원문·번역 검사는 유지하며, 연결 누락은 보고서 인용발명 번호와 업로드 자료 번호를 함께 표시한다.

분석·검색 지침은 `backend/app/task_instructions.py`에서 보고서 계약과 함께 버전 관리한다. 프롬프트 탭, 저장·편집·가져오기·내보내기 API 및 기본 프롬프트 설정은 제거했다. 과거 설정이나 `PRISM_PROMPT_DIR` 환경 변수는 새 실행에 반영하지 않는다. `prompt/`의 과거 파일은 실행 시 읽지 않는다. 실행 요청의 `prompt_id` 교체는 거절한다. 실행 기록의 지침 스냅샷과 최종 입력 조회는 감사·재현을 위해 유지한다.

후속 위치 정정: 유효한 선택 번호가 잘못 지정된 경우에도 같은 문헌의 실제 전달 원문에서 quote 전체가 유일하게 정확 일치하면 위치를 정정한다. 원 선택 번호와 정정 사유를 근거 메타데이터에 보존하며, 원문·번역 범위는 바꾸지 않는다. 자세한 재현 및 저장 기록 수정은 `report-auth-and-location-fix-2026-09-28.md`를 참조한다.

2026-09-29 차이점 서술 변경: 새 resolution은 gap/evidence/supplements/derivation/remaining_difference/conclusion을 사용한다. supplements는 보완 문헌별 attachment/evidence/explanation이며 주 문헌을 넣을 수 없다. 프로그램이 보완 근거만 인용하고 주 문헌은 부족한 한정에서만 언급한다. 주 문헌 근거는 검증에 연결하되 발췌를 반복 출력하지 않는다. 이전 explanation 응답은 호환하지만 주 문헌 직접 발췌는 구성대비 참조로 처리한다. 신규 응답은 별도 필드로 기존 대응 설명의 반복을 피한다. 실측 재검토는 report-substantive-review-2026-09-29.md에 기록했다.
