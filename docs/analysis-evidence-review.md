# 구성대비 보고서의 근거 재검토

새로 실행하는 특허 분석에는 초안 생성 후 원문 대조와 별도의 AI 의미 재검토가 적용된다. 이전에 저장된 보고서는 자동으로 재작성하지 않는다.

## 구성별 발췌

1. 초안에서 구성마다 문헌별 대안 구절과 동의어 검색어를 받는다.
2. 첨부에서 추출한 원문과 페이지를 대조한다. 공백 차이는 허용하지만 문장을 합성하거나 존재하지 않는 구절을 인용할 수 없다. 위치와 원문 해시를 기록한다.
3. 초안이 선택하지 않은 문헌도 포함해, 읽을 수 있는 모든 인용 첨부에서 검색어 기반 대안을 추가한다. 한국어·영어 외에 일본어·중국어 표현과 숫자·단위도 검색어로 사용한다. 단어 일치는 후보 수집에만 사용한다.
4. 동일한 실행 도구의 별도 AI 호출이 청구항과 후보들을 비교한다. 초안의 점수나 결론을 제공하지 않고 주체·동작·대상·조건·입력·출력·관계를 평가한다. 직접 대응, 부분 대응, 단어만 유사, 관계 불일치, 미확인을 구분한다.
5. 직접 대응 판정과 세부 조건이 충돌하거나 원문·선택 근거가 확인되지 않으면 확정 점수를 주지 않는다. 최종 인용문은 프로그램이 원문에서 가져온다.

최종 보고서에는 구성×문헌 대응표, 선택 이유, 원문·번역·위치, 조건별 판정, 대안 후보 비교를 싣는다. 유사도는 AI의 보조평가이며 정확도나 확률이 아니다.

## 한정별 복수 근거와 차이점 해소

- 별도 재검토 호출은 구성 문언을 연속된 원문 구간으로 분해한 `limitations`를 반환한다. 프로그램은 공백을 제외한 원문 일치와 문언의 포함 범위를 확인한다. 부정·배타 조건, 수치·단위·부등호가 빠지면 근거 묶음을 확정하지 않는다. 이 검사는 **이미 선언된 구성 내부**의 누락을 검사하며, 전체 청구항에서 처음부터 구성 자체가 누락됐는지까지 보장하지 않는다.
- `evidence_sets`는 한 문헌의 같은 실시예에서 나온 하나 이상의 구절을 연결한다. 각 구절의 원문·번역·페이지를 보존하며 문장을 합성하지 않는다. 모든 한정에 직접 근거가 연결되고, 동일 실시예의 연결 이유와 근거가 있으며, 조건별 판단이 일치할 때 직접 대응으로 채택할 수 있다. 여러 문헌, 다른 실시예, 불명확한 연결, 잘못된 근거 ID 및 누락된 한정은 직접 대응 묶음으로 승인하지 않는다.
- `derivations`는 단일 문헌에서의 변경과 복수 문헌 결합을 구분한다. 한정별 근거, 필요한 변경, 원문에 연결된 동기·양립 가능성·장애, 남는 차이와 검토 결과를 최종 보고서에 표시한다. 재검토에서 원문과 의미 판정이 확인된 후보만 참조할 수 있다. 근거가 없으면 초안의 결론을 복사하지 않고 도출·결합 검토의 자료 부족을 표시한다.
- 결합으로 부족 구성을 보완할 수 있다는 평가가 나와도 단일 문헌의 유사도·직접 대응 수·보완 검색 대상 여부는 올리지 않는다. 결합에 사용하는 문헌은 번호를 부여해 보존하지만, 결합에 포함됐다는 이유만으로 주 인용발명으로 선택하지 않는다.
- 구성×문헌 대응표와 문헌 선정에는 검증된 동일 문헌 근거 묶음의 대응 정도를 반영한다. 보고서에는 한정별 대응표와 복수 원문, 구절을 함께 사용할 수 있는 이유가 함께 출력된다.
- 기존 형식의 개별 구절 평가는 후보 비교표에 남기지만, 한정별 근거 연결이 없는 선택은 최종 점수나 문헌의 직접 대응 수에 반영하지 않고 미확인으로 남긴다. `review.json`의 버전은 2이며 한정·근거 묶음·도출 경로를 보존한다. 공개 구성 매니페스트와 문헌 번호 형식은 유지한다.

## 인용발명 선정과 번호

명시적으로 구별할 수 있는 독립항의 직접 대응 구성 수, 전체 직접 대응 수, 새로 보완하는 구성 수, 대응 개선량 순으로 문헌을 선택한다. 이미 선택한 문헌의 대응 범위를 반영해 후속 문헌의 추가 기여를 계산한다. 동률은 문헌 해시로 정하며 구성별 최선 근거로 선택된 문헌도 보존한다.

기존 번호를 유지하는 후속 분석에서는 첨부 ID 또는 해시가 같은 문헌의 번호를 유지한다. 주 인용발명과 번호가 반드시 같지는 않다. 이 선정 규칙은 기술적 구성 대응을 정리하는 규칙이며 신규성·진보성 판단 전체를 자동 검증하는 규칙은 아니다.

## 시간·실패 처리와 한계

- 재검토는 최대 12회, 총 240초와 해당 작업의 남은 실행시간 중 짧은 범위에서 수행한다. 한 번에 최대 4개 구성과 제한된 입력량을 처리한다. 실제 추가시간은 구성·문헌 수와 실행 도구에 따라 달라진다.
- 입력량·시간 제한, 판독 실패, 불완전한 응답은 미확인과 검토 제한으로 표시한다. 검토하지 않은 부분을 대응 없음 0%로 바꾸지 않는다.
- 후보 블록 자체가 없으면 기존 본문을 **미검증 초안**으로 표시한다. 검토 가능한 결과가 있으면 재검토 결과로 보고서를 생성한다.
- 실행 산출물의 `analysis_evidence/review.json`에 후보·원문 위치·재검토·문헌 선정 기록을, `draft.md`에 초안을 보존한다. 추가 AI 호출 사용량도 합산한다.
- 원문 확인은 PDF 이미지 자체가 아니라 추출된 텍스트 기준이다. OCR 오류, 표·도면 해석, 후보 누락, 의미 평가와 번역 오류는 남을 수 있다. 최선이라는 표현은 검토 후보 범위에 한정된다.
- 자동 테스트는 원문 위조 거부, 조건 충돌, 후보 선택, 번호 보존, 시간 제한, API 연결 외에 페이지를 넘는 복수 근거, 다른 문헌·실시예의 혼합 거부, 한정 누락, 결합 근거 참조, 잔존 차이 보존 및 결합에 의한 점수 상승 방지를 확인한다. 모의 AI 응답을 사용하므로 실제 특허 사례의 의미 정확도를 측정한 결과는 아니다. 동일 실시예 여부와 결합 동기의 타당성은 여전히 AI의 의미 평가이며, 프로그램의 참조·형식 검증 자체가 그 타당성을 증명하지는 않는다.
