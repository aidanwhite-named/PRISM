# 미발견 판단을 발췌 누락으로 오인한 검사 수정

대상 작업: `3e47bb72-d96f-4eec-add2-ac8af6993603`.

## 원인

청구항 3 (A)~(C), 청구항 4 (B)~(D)는 원응답에서 유사도 0%, 대응 근거 빈 목록,
차이 해소 상태 `insufficient`로 작성되었다. 문헌 이름은 긍정적인 대응 근거가
아니라 ‘검토했지만 필요한 내용을 찾지 못한 문헌’을 가리켰다.

검사기는 문헌 언급을 모두 긍정 인용으로 취급했다. 이 때문에 여섯 구성의
부재 설명과 그중 두 구성의 두 문헌 검토 설명에서 총 열 개의 발췌 누락 경고가
발생했다. 기존 단일 근거 번호·해소 결론 형식 수정과는 별개의 의미 구분 오류다.

## 변경

- component와 resolution에 문헌별 `reference_roles`를 명시하도록 출력 계약을 변경했다.
  `support`는 긍정 근거, `not_found`는 제공 범위에서 대응 근거 미발견,
  `unavailable`은 확인 불가다. 긍정 기재와 부재를 함께 설명하는 문헌은 support다.
- 문헌 이름의 등장과 긍정 근거 사용을 구분한다. 미발견 문헌의 존재와 실제 제공
  자료 범위를 검사하고, 대응 점수·확인 불가 상태와 충돌하는 선언은 경고한다.
- support에는 기존의 항목별 연결·문헌 일치·원문·번역 검증을 유지한다.
  참조 역할을 바꿔 없는 근거나 다른 문헌의 발췌를 통과시킬 수 없다.
- 구형 응답은 0%/insufficient, 연결 근거 없음, 알려진 제공 문헌,
  명확하게 부정적인 설명이라는 조건이 함께 맞을 때만 호환 처리한다.
  긍정 또는 혼합 설명은 기존 검사를 유지한다.
- 미발견을 ‘출력 오류’ 대신 ‘대응 근거 미발견’으로 표시한다. source_reviews에
  선언/호환 판별 경로, 실제 전달 source ID, 전체 자료/검색 발췌 범위를 기록한다.
  이는 AI의 검토 결과이며 문헌 전체의 부재를 프로그램이 증명했다는 뜻이 아니다.
- 구성대비의 근거 검사 실패도 comparison_checks 상태에 반영하여 점검 상태와
  상세 오류 목록이 일치하도록 했다.

## 검증 및 복구

- 문헌 참조 역할·구조화 보고서·근거 교정·원문 전달·내장 지침 192개 테스트 통과.
- 실제 원응답 재생: 점검 경고 10개 → 0개. 기존 근거 10개 모두 검증 유지.
- 구성별 점수, 여섯 개의 0% 판단, 차이·분석 문장, 번역·원문, 문헌 매핑을 그대로 보존했다.
- 원 모델 응답은 변경하지 않았고 추가 모델 호출은 없다.
- 원래 보고서 파일과 변경할 DB 필드를 실행 폴더의
  `report-reference-roles-20260930/original`에 백업한 후 저장 보고서와 다운로드 자료를 복구했다.
- 실행 중인 앱의 API에서도 경고 없음과 ‘대응 근거 미발견’ 표시를 확인했다.
- 현재 프로세스에 새 검사 코드를 반영하려면 앱 재시작이 필요하다. 앞선 서버
  재시작 작업이 도구 정책으로 거절되어 이번 작업에서는 우회하지 않았다.
