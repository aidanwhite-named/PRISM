# 모델 주도 병렬 수집과 후보 상한

## 변경

- `start_collection`은 모델이 작성한 EPO CQL, 키프리스 한국어 질의, OpenAlex 영문 질의를 최대 3개 작업 스레드에서 시작하고 즉시 반환한다. 모델은 API를 기다리는 동안 네이티브 웹 검색을 할 수 있다. `collect_results`는 대기 없이 완료 결과와 진행 중 출처를 알려준다. 한 출처 실패가 다른 출처 결과를 버리지 않는다.
- API 페이지는 출처별 기본 3건, 최대 4건이다. 별도 API 호출에도 같은 상한을 적용한다. 질의·페이지 확장은 모델이 선택한다. 호출 예산 예약과 JSONL 기록은 스레드 잠금으로 보호하고, 같은 백엔드 접근은 직렬화한다.
- `save_candidates`의 유력 후보 목록은 최대 15건이다. 초과 저장은 기존 목록을 보존하며 거절한다. `replace=true`로 모델이 다시 선별·정렬한 목록을 저장하고 제외 이력을 남긴다. 마지막 출력의 초과 후보도 모델 제시 순서에 따라 상한 밖 감사 기록으로 옮긴다. 임의 유사도 점수를 만들지 않는다.
- 마감 분류에 원시 API 검색 결과를 자동 편입하지 않는다. 원시 결과는 검색 이력에 남으며 최종 검토는 모델이 선정한 후보만 받는다.
- Windows의 동시 읽기/원자적 파일 교체 충돌(WinError 32)을 회귀 검증에서 발견하여 공유 JSON 교체를 짧게 재시도하도록 수정했다. 기존 완전한 JSON을 유지하고 교체 실패를 성공으로 숨기지 않는다. 호출 카운터도 같은 쓰기 경로를 사용한다.
- `save_candidates.x_review`에서 모델이 청구항의 모든 필수 구성·관계와 전체 대응 이유를 명시하면, 각 구성의 근거를 보존된 청구항·명세서·전문 필드와 대조한다. 초록만의 근거, 누락·불일치 문장, 기준일이 설정된 경우 공개일 미확인은 종료를 허용하지 않는다. 기술적 대응과 핵심 구성 추출 자체는 모델의 판단이다.
- 통과한 X 검토는 원자적으로 종료 신호를 저장한다. 실행기가 다시 근거를 확인하고 탐색 프로세스를 종료한 뒤 보고서를 반환한다. 추가 조회를 차단하고 대기 중 수집을 취소한다. 이미 전송된 외부 요청의 과금·할당량은 되돌릴 수 없다. 사용자 취소와 인증·도구정책 오류는 성공으로 덮지 않는다.

## 검증

최종 관련 회귀 테스트: 99개 통과(`test_search_session`, `test_search_agent_tools`, `test_search_deadline`, `test_search_strategy_prompt`, `test_search_api`, `test_agy_mcp`; 외부 로그인에 의존하는 live_cli 제외).

실행 `6e118d15-ab88-43ee-b116-77d936d4fa9a`: 동일 관절 청구항, agy / gemini-3.8-flash-medium, 253.05초, SUCCEEDED. 최종 6건(Y 3, Z 1, 자료 부족 2). X가 없어 탐색 시간 구간 종료 후 마감 분류로 완료했다.

첫 API 요청들은 07:01:38.582 / .586 / .590 UTC에 시작하여 실제 동시 실행을 확인했다. API 응답은 07:01:40.332까지 완료됐고 첫 웹 호출은 07:01:43.335였다. 이번 실행에서는 API가 빨라 웹 요청과 네트워크 대기 시간이 실제로 겹치지는 않았다. 비차단 수집과 웹 작업 가능 여부는 스레드 장벽 테스트로 확인했다. `collect_results` 전 웹 검색을 수행했다.

별도 결정론적 테스트는 병렬 실행·독립 실패, 후보 상한·교체, 원시 44건 미편입, API 페이지 3/4건 제한, 원문 기반 X 허용, 초록·누락 근거·알 수 없는 공개일 거절, 프로세스 종료 및 사용자 취소 보존을 검증한다. X 자동 종료는 이번 실제 검색에서 발생하지 않았으므로 실문헌 X 조기 발견 성공을 주장하지 않는다. 마지막 독립 API 페이지 상한 보완은 실제 검색 시작 후 추가되어 별도 테스트로 검증했다.

기록: [실행 요약](artifacts/joint-search-comparison-20260917/parallel-shortlist-run.json).

확장 검증에서 기존 비활성 progressive 엔진의 `test_domestic_lane_precedes_early_seed_success`는 기존 코드의 현재 실행 순서와 맞지 않아 실패했다. 이번 변경 경로의 회귀 검증과 분리했으며 해당 엔진 코드는 변경하지 않았다.

별도 설치 CLI 점검에서 Codex의 capabilities 호출은 통과했고 Claude는 미로그인 응답으로 실패했다. Claude 인증 설정은 변경하지 않았다. 실제 검색 검증은 사용자 실행에 사용한 agy로 수행했다.

## 키프리스

실제 진단에서 코드 31(DEADLINE_HAS_EXPIRED_ERROR), 후속 실행에서 코드 30(SERVICE_KEY_IS_NOT_REGISTERED_ERROR)을 관측했다. 원인을 하나로 단정하지 않고 코드별 한국어 조치 안내와 동일 실행 재호출 방지를 추가했다. 키·상품 승인·이용기간의 외부 계정 상태는 복구하지 못했다. 사용자 요청에 따라 추가 키프리스 진단은 중단했다.
