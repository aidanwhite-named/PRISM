# 검색 후 필드 보완 구조 변경

## 동작

- 최초 검색이 끝나면 검증·검색 기준일 필터를 적용한 후보를 DB에 저장하고 `search_preview_ready` 이벤트를 보낸다. 화면은 작업이 끝나기 전에도 이 결과를 표시하며 추가 확인 중임을 알린다.
- 저자·날짜 등의 결측만으로 두 번째 모델 실행을 시작하지 않는다. 현재 허용 정책에서 제공된 도구 중 문헌별 미시도 스코프만 Python이 직접 조회한다. 서지 누락에는 biblio만, 원문 근거 자체가 없으면 논문 abstract/특허 claims를 고려한다. 실패·빈 응답·진행 중 요청도 이미 시도한 것으로 보아 자동 반복하지 않는다.
- 직접 보완 조회는 남은 호출 예산 안에서 최대 4회다. 시작 후 30초가 지나면 새 조회를 시작하지 않는다. 진행 중 요청에는 기존 HTTP 클라이언트의 타임아웃이 적용된다. 모든 응답·실패는 기존 journal에 보존한다.
- 인용 보완은 원문 근거와 evidence_ref가 이미 일치하는 항목 중 원문과 대조되지 않은 support_text만 고려한다. 원문 필드가 6천 자 이내인 최대 2항목을 동일 provider/model에 한 번 전달한다. 원문이 없거나 너무 크면 미확인으로 남긴다.
- 이 보완 요청에는 전체 검색 프롬프트, 첨부 문서, 다른 후보 전체를 넣지 않는다. MCP와 외부 도구를 비활성화하고 최대 30초(기존 전체 마감보다 짧게)로 제한한다. 출력에서는 허용된 후보·mapping의 support_text만 취하며 원문 연속 문자열 검사와 보존 근거 검증을 다시 거친다. 후보 추가·순서·분류·대응 설명 변경은 받지 않는다.
- 보완할 새로운 정보가 없으면 미확인 사유를 표시하고 종료한다. 결측을 확인 성공으로 바꾸지 않으며, 검색 기준일이 있는 경우의 날짜 검증도 유지한다.
- 취소 시 최초 결과와 확인된 단계의 usage를 보존하는 기존 수정은 유지한다.

## 추가로 발견한 원인

Crossref의 `author` 객체 목록과 `issued.date-parts`는 실제 응답에 있어도 기존 코드가 근거 경로를 만들지 않아 `text_fields`에서 빠졌다. 원본 JSON에서 저자·날짜를 결정적인 방식으로 재추출하는 경로를 추가했다. 연도/연월만 주어진 날짜에 월·일을 만들어 넣지 않는다. 회사 번역·약칭을 같은 회사라고 추정하지 않는다.

## 검증

- 관련 백엔드 테스트 262개, 프런트엔드 테스트 16개 통과 및 빌드 성공.
- 미시도 스코프 판단, 실패/빈 응답 재조회 제외, Python 단건 보완, 도구 없는 인용 보완, 원문 외 문장·후보 변경 거절, 보완 중 취소/타임아웃, 최초 결과 선표시, Crossref 근거 재추출을 테스트했다.
- 보존된 실행 `c1eca403-741b-40ac-9943-245a0847fd10`의 최초 출력과 최초 도구 journal로 재평가했을 때 추가 조회 0회, 인용 모델 요청 0회였다. 미확인 항목은 남는다. 이는 로컬 재평가이며 실시간 검색의 품질·전체 토큰·실행 시간 절감률을 측정한 결과는 아니다.
- 모델 교체, 다른 계정 사용, 검색 간 영구 레코드 캐시는 이번 범위에 포함하지 않았다.
