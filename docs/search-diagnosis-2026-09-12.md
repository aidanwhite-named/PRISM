# PRISM 검색 실패·지연 조사 (2026-09-12)

## agy: 인증/모델 선택보다 공통 검색 경로의 실패

- 사용자 실패 작업: `2e60f677-e604-4c8e-929c-d608354747be`. 26ms에 사전 차단되었고 usage는 null이다. 이 작업은 모델을 실행하지 않았다.
- 설치된 CLI: agy 1.2.2. `agy models`는 성공하며 선택 모델 `gemini-3.8-flash-low`도 목록에 있다.
- 현재 모델 Flash와 다른 계열 `gemini-3.1-pro-low`에서 각각 검색을 정확히 한 번 요청했다. 두 실행 모두 모델 응답은 완료되고 `auth_required=false`였지만 `search_web`은 `no summary returned from GenerateContent`로 실패했다.
- agy 자체 `~/.gemini/antigravity-cli/cli.log`에도 `search_web_handler.go:89`의 동일 오류가 있다. PRISM의 출력 해석만 잘못된 경우가 아니다.
- 따라서 로그인 만료나 특정 선택 모델에만 생기는 오류라는 증거는 없다. 공통 검색 내부 단계가 필요한 요약 응답을 못 받는 현상이다. CLI 회귀와 서버 측 장애 중 어느 것인지는 공개된 오류 정보만으로 확정할 수 없다. 로그인 초기화·CLI 교체를 임의로 하지 않았다.
- PRISM의 agy 어댑터에는 실행별 EPO/논문 MCP 연결이 구현되지 않았다. 이는 agy 자체가 MCP를 전혀 지원하지 않는다는 뜻은 아니다. Kiwee는 별도로 미구현이다. 따라서 웹 검색이 막히면 현재 PRISM agy 경로는 사용할 검색 채널이 없다.
- 검색 도구 확인 API가 저장된 선택 모델을 실제 테스트에 넘기도록 수정했다. 이전에는 CLI 기본 모델로 확인했다.

진단용 모델 호출에는 사용량이 발생했다. 실패한 사용자 작업의 사용량과 구분해야 한다.

## 확인한 낭비와 수정

1. 자동 검증이 후보 9건 전체를 다시 전달하고 전체 보고서를 다시 쓰게 했다. 이제 미검증 후보와 필요한 기존 근거만 보내며, 수정 후보만 받아 원래 결과에 병합한다. 수정하지 않은 후보, 후보 순서·그룹, 최초 검색 라운드·용어 확장·실패 기록을 보존한다. 후보 추가·그룹 변경·중복 수정·검증 범위 밖 변경은 거절한다.
2. 이미 받은 초록을 다시 조회했다. 후속 프로세스에는 기존 도구 대화가 없는데 프롬프트도 기존 근거를 전달하지 않았기 때문이다. 이제 검증된 원문 필드와 evidence_ref를 중복 없이 전달하고 이전 fetch 성공·실패도 알려 준다.
3. MCP 응답에 같은 JSON을 content와 structuredContent로 두 번 보냈다. outputSchema를 광고하지 않는 현재 도구에서는 완전한 JSON 텍스트 한 벌만 보내도록 변경했다. 보존 저널은 그대로다. 기존 26개 응답을 재직렬화하면 549,643바이트 → 275,575바이트로 49.9% 줄었다. 전송량 절감이지 곧바로 같은 비율의 과금 토큰 절감을 뜻하지는 않는다. [MCP 도구 결과 규격](https://modelcontextprotocol.io/specification/2025-06-18/server/tools).
4. 새 프로세스에서 논문 근거 재검증 프로필이 등록되지 않을 수 있었다. MCP 검색은 다른 프로세스에서 실행되므로 웹 프로세스의 파서 등록까지 보장하지 못했다. 검증 진입점에서 등록하여 저장된 근거가 거짓 미검증으로 판정되는 것을 막았다.
5. 후속 검증 감사 기록에 단계별 사용량, 소요 시간, 전달 후보 수·입력 글자 수를 추가했다.
