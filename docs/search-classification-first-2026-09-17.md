# 초록 기준 분류를 원문 확보보다 먼저 저장

## 변경

기존 선별 호출은 후보 ID만 반환했고, XYZ는 원문 확보와 passage 추출 뒤의 검증 호출에 묶여 있었다.
심층 검색의 초반에 빠른 검색의 45초 마감을 중첩 적용하므로 계획이 28초 걸리면 관계 검색이 생략될 수 있었다.

- 기존 `triage` 호출 하나가 상위 최대 8개 문헌을 비교해 XYZ/null, 이유, 검토 상태와 원문 확인 대상 최대 3개를 함께 반환한다. 후보가 1~3개일 때도 실행한다.
- 분류 결과를 먼저 저장·게시한 다음 선택한 문헌만 원문 확인한다. 같은 실행의 검증 호출은 한 번이며, 별도 분류 재시도나 계획 복구 모델 호출은 추가하지 않는다.
- 초록 판단은 `basis=abstract`, `provisional=true`로 표시한다. 제목·검색 스니펫만으로 XYZ를 부여하지 않는다. 인용문 대조와 충분한 원문 근거를 가진 X/Y의 판정은 유지한다.
- `classified`, `insufficient_information`, `low_relevance`를 구분한다. 응답 누락 문헌은 미평가다. 낮은 관련성은 명시적으로 다른 분야·관계라는 검토 결과여야 하며, 초록에 내용이 없다는 이유만으로 판정하지 않는다.
- 뒤의 원문 확인이 실패하거나 근거가 부족해도 기존 분류를 지우지 않는다. 원문 검토에서 새로운 분류나 명시적 낮은 관련성이 반환되면 수정할 수 있다.
- 선별 대상 중 응답이 빠지면 `classification_incomplete`로 기록하고 작업을 성공으로 표시하지 않는다. 후보·부분 분류·usage·checkpoint는 보존하며, 기존 정밀 검색 이어가기를 사용할 수 있다. 모든 대상에 null/자료 부족/낮은 관련성 응답이 온 것은 응답 완료이며, XYZ 문헌을 찾았다는 뜻은 아니다.
- 대상 수·검토 응답 수·미평가 후보 수를 표시한다. 상위 8개 응답 완료를 전체 후보 검토 완료로 표시하지 않는다.
- 계획에서 구성별 질의·동의 구절·관계 설명 중복 생성을 없애고, 원 청구항의 구성 발췌·검색용 용어·관계 질의 2개와 국내 질의만 생성한다. 전체 원 청구항과 사용자가 선택한 전략은 선별·검증에도 그대로 전달한다.
- 관계 질의를 앞의 4단어로 자르지 않는다. 대체 질의도 분야와 관계를 유지하며 일반 단어만으로 구성별 확장하지 않는다. 긴 관계 질의는 잘라서 의미를 바꾸는 대신 계획 파싱에서 제외한다.
- 전체 시간 상한은 빠른 검색 45초 / 심층 120초 / 정밀 300초 그대로다. 초반 45초 중첩 마감과 관계·인용 단계의 별도 마감을 없애고, 수집 마감 하나로 분류 시간을 예약한다(최대 45초, 전체 예산의 40%, 최소 15초). 기존 HTTP 개별 접속 제한은 유지한다.
- 계획은 기존 최대 30초 범위 안에서 제한하고, 빠른 검색에서는 전체 예산의 25%를 사용한다. 초기에 20초로 줄였으나 실제 agy 실행에서 시간 초과가 관측되어 심층 검색은 기존 상한으로 되돌렸다. 전체 시간을 늘린 변경은 아니다.
- 실제 실행에서 발견한 agy 모델 이름의 `-medium`과 자동 `--effort low` 충돌도 수정했다. 자동 추론 강도는 선택한 agy 모델의 접미사를 존중하며, 별도 명시한 추론 강도는 우선한다. Provider가 명시한 오류를 단순 JSON 파싱 실패로 숨기지 않는다.

## 검증 범위

회귀 검증은 원문 접속/검증 실패 시 분류 보존, 일부 분류 누락, 자료 부족과 낮은 관련성의 구분,
제목만으로 XYZ 부여 차단, 날짜 이후 문헌·가짜 ID 배제, 28초 계획 후 관계 질의 보존,
수집 마감 후 분류 시간 확보, 원문 검토에 따른 분류 변경, 과거 checkpoint 이어가기를 포함한다.
API에서는 분류 실패 작업의 실패 표시·부분 결과·이어가기를 확인한다. 화면에서도 잠정 근거 범위와 검토 상태를 확인한다.

이 PC에는 사용자가 인용한 최신 실패 실행의 원본이 없어 이전 성공/실패의 동일 조건 비교는 할 수 없다.
실검색은 현재 저장 설정인 agy / gemini-3.8-flash-medium / 심층 검색으로 별도 실행했다.
과거 Codex 실행과 모델·캐시 조건이 다르므로 시간이나 검색 품질의 전후 향상률로 해석하지 않는다.
키프리스는 키·승인·월간 한도 확인이 필요한 API 오류를 반환했다.

- `2351cd09-156d-4e60-a2bf-d10a07abdb97`: 모델/추론 강도 충돌로 실패. 수정 전 환경 문제 확인용.
- `b520d1bc-e2cf-4e49-8562-7f00fbdf4610`: 충돌 수정 후 61.297초, 후보 1개, 분류 응답 1개. 계획 20초 제한 초과 후 검색 단서 후보를 자료 부족으로 판정. 알려진 정답 문헌은 찾지 못했으며 XYZ 검색 성공 사례로 집계하지 않는다.
- `c7c95165-be96-45cd-a0c4-1e56cf243fab`: 계획 상한 복원 후 114.36초. 계획 14초, 첫 후보 16.5초, 후보 98개, 선별·분류 응답 약 34.3초. 상위 8개 응답을 원문 확인 전에 저장했고 최종 Y 3개 / Z 1개 / 자료 부족 3개 / 관련성 낮음 1개다. 나머지 90개는 미평가다. 초록 인용문 대조 11개, 전문 확보 0개, 질의 캐시 사용 0개. 알려진 정답 EP4386678A1/KR20250121108A는 후보에 없었다. 분류 경로의 실동작을 확인했지만 정답 검색 및 분류 정확도 개선을 입증한 결과는 아니다.

마지막 실행에서 일부 Y 이유가 기술 관계보다 주제 유사성에 치우쳐, 분류·검증 지시에
공통 주제/데이터형/목적만으로 Y를 부여하지 말고 대응 관계와 빠진 연결을 명시하도록 보강했다.
이 마지막 지시 문구의 정확도 효과는 별도 실검색으로 재측정하지 않았다.

자동 검증: 관련 백엔드 87개, 화면 22개 테스트 통과. TypeScript 및 production build 통과.
