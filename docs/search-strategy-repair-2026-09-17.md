# 검색 전략·문헌 분류 수정 및 재검색

2026-09-17. 사용자가 보고한 몰입형 비디오 청구항으로 실행을 재현하고 수정했다. 기존 UI, DB, API와 단계별 검색 구조를 유지했다.

## 수정한 동작

- `search_engine/planner.py`: 서두·참조번호·연결문구가 분해 결과에 모두 포함되지 않았다는 이유로 유효한 영어 검색 계획을 버리던 검사를 제거했다. 유효한 구성은 보존하고 잘못된 항목만 기록한다. 계획 생성 실패 시 남은 예산 안에서 영어 질의 복구를 한 번 시도한다. 최종 fallback도 `(A)` 표기를 인식한다.
- `search_engine/engine.py`: 첫 검색의 구성 3개 제한을 제거하고 요청의 질의 예산 안에서 각 구성을 조회한다. 원 청구항 전체와 선택한 검색 전략을 계획·후보 검토·원문 검증에 전달한다. 분해 결과가 원 청구항을 대체하지 않는다.
- `api/jobs.py`, `search_engine/job.py`: 새 검색에서도 선택한 기존 검색 프롬프트를 실제로 사용한다. 요청 → 설정 기본값 → 배포본 순서로 선택하며 프롬프트 ID·이름·본문 해시를 감사 기록에 남긴다. 실행 도구와 JSON 출력 계약은 프로그램이 관리한다. 전략의 모든 확장 지시가 매 요청마다 실행되는 것은 아니다.
- `search_engine/models.py`, `passages.py`, `report.py`: 문헌 분류는 `document_classification`에, 청구항 구성은 `features[].id`에 별도로 저장한다. 기존 검증 호출이 분류와 이유를 함께 반환하므로 분류 전용 LLM 호출은 추가하지 않는다. A/B/C는 관련성 유형이며 기계적인 유사도 등급이 아니다.
- `passages.py`: 같은 문헌의 인용문은 어느 구성 검색으로 발견했든 다른 구성의 근거로 사용할 수 있다. 문헌 일치 및 실제 인용문 대조는 유지한다. 인용 검증과 관계 해석의 정확성은 별개다.
- 화면에서 기존 검색 전략 선택, 문헌 A/B/C 필터와 분류 이유를 제공한다. 확인하지 못했거나 관련성이 불충분한 후보는 미분류로 보존한다. 분류가 있다고 모든 구성의 인용 검증이 완료된 것은 아니다.
- `inference.py`: Codex의 캐시 입력·추론 출력 토큰 필드를 집계한다. 캐시 토큰을 입력에 다시 더하지 않는다. 실제 달러 비용을 확보하지 못한 경우 추정 금액을 표시하지 않는다.

문헌 분류 정의는 A: 전체 구조와 핵심 특징 유사, B: 전체 구조는 다르나 핵심 관계 유사, C: 전체 구조는 유사하나 핵심 대응은 부분적이다. 구성 A/B/C/D와 독립적으로 적용한다.
