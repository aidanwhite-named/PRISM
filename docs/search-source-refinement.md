# 검색 중 원문 대조와 보완 검색

검색 버튼 실행 안에서 후보 탐색 → 유력 후보 원문 확보 → 핵심 특징·관계 대조 → 부족한 관계를 이용한 보완 검색을 수행한다. 별도 구성대비 작업이나 버튼을 실행하지 않는다. 기존 검색 전략의 X/Y/Z 분류와 구성 대응표 요구는 유지한다.

## 원문과 판단

source_fetch는 Google Patents의 표시된 청구항·상세설명 또는 공개 PDF를 제공한다. 웹페이지·초록·검색 단서는 원문 검증으로 승격하지 않는다. 모델은 save_findings.review에 판단(strong/partial/mismatch/unavailable), 이유, 잔존 차이, 후속 검색어와 원문 근거를 저장한다. 각 근거에는 청구항 특징·관계, 원문, 같은 범위 번역과 capture_artifact_id가 포함된다.

프로그램은 실제 제공한 응답 안에서 원문 문자 일치와 문헌 연결을 확인한다. 다른 문헌·다른 패밀리의 원문, 읽지 않은 구간, 변형 발췌, 번역 누락은 검증 실패다. PDF는 페이지 범위, HTML은 섹션·추출 문자 위치를 보존한다. 기술적 대응과 번역 의미의 정확성은 모델의 판단이며 문자 일치 검사가 보증하지 않는다. 원문 접근 불가는 기술적 불일치와 구분한다. source_fetch를 사용할 수 없는 제공자의 웹 열람은 이 자동 검증으로 인정하지 않으며 미확인 상태가 남을 수 있다.

## 보완 검색과 비용 제어

- 저장 도구는 미확인 상위 후보와 부족한 관계를 즉시 모델에 반환한다. 같은 검색 세션 안에서 이를 이용해 재검색할 수 있다.
- 세션이 끝나도 확인할 후보나 차이가 남으면, 같은 작업 안에서 최대 두 번 추가 검토·검색을 호출한다. 같은 미해결 피드백이 반복되면 중단한다. 별도의 정식 구성대비 보고서를 생성하지 않는다.
- 전체 제한시간은 기존 설정을 사용한다. 45초 이상이면 최초 호출에 남은 시간의 60%를 배정해 확인·보완 시간을 확보한다. 남은 시간이 15초 미만이면 후속 호출하지 않는다. 취소·시간 종료 시 확보 결과를 보존한다.
- 동일 URL의 청구항·상세설명·본문은 원 응답을 재사용한다. source_fetch.find로 관련 용어 주변 구간을 읽을 수 있다. 발췌 검증에는 추가 모델 호출이 없다. 각 모델 호출의 사용량을 합산하며 실측 비용이 없으면 절감률을 주장하지 않는다.
- 검색 회차별 입력·응답과 검토 근거를 저장한다. 과거 이력을 덮어쓰지 않는다.

## 표시

원문 근거가 확인된 strong/partial 후보를 먼저 표시하고, 확인되지 않은 후보와 mismatch를 구분한다. 검토한 후보의 이유·차이는 원문 검토 결과로 갱신하며 mismatch는 추천 구성대비 선택에서 제외되도록 관련성 낮음으로 표시한다. 사용자 수동 선택은 유지한다. UI·다운로드 보고서에 원문 검토 상태와 근거가 표시된다. 자동 검증이 끝나지 않은 후보는 확정 대응처럼 표시하지 않는다.

## 검증

자동 검색→불일치 저장→후속 검색 입력→원문 확인 결과 저장, 잘못된 발췌/문헌/초록 거부, 미확인 분리, 중복 피드백 중단, 누적 사용량, 시간 종료·취소, API 검색·계속 검색, 원문 캐시 재사용 및 상세설명 구간 조회를 테스트한다. 실제 외부 LLM 검색의 품질·비용 비교 실험은 별도이며 자동 테스트를 그 실측으로 간주하지 않는다.
