# 최종 보고서 근거 패키지 중복 제거

검색 라운드(5회), 열람 한도(80쪽), 라운드 반환 한도(56,000자), 근거 패키지
상한(100,000자) 및 실행별 바이트 한도는 변경하지 않았다.

## 변경

- 같은 문헌·PDF 페이지의 페이지 전문, 근거 발췌, 앞뒤 문맥, 서지 발췌가
  완전히 같은 텍스트를 포함하면 공유 원문에 한 번 싣는다. 구성별 출처와 관련성
  메모에는 원문 번호와 문자 범위를 연결한다. 다른 문헌이나 페이지는 합치지 않는다.
- 원문의 공백·개행·문자와 구성별 인용 관계를 보존한다. 유사도 기반 삭제,
  요약, 문단 재작성, 추정에 의한 겹침 결합은 하지 않는다.
- 서지 발췌가 첫 비어 있지 않은 페이지에서 나온 경우 실제 PDF 페이지를 기록한다.
  페이지 위치가 없는 과거 패키지의 서지 발췌는 기존처럼 직접 수록한다.
- 근거를 수집할 때도 중복 원문을 다시 예산에 넣지 않는다. 페이지 확장에는
  발췌가 이미 차지한 원문 공간을 재사용할 수 있게 하고, 최종 렌더링의 실제
  문자 수와 UTF-8 바이트 수를 기존 `fit()`에서 모두 검사한다.
- 공통 검토 제한은 한 번만 적고 구성 고유의 제한은 남긴다. 검색 실행의
  우선순위 재평가 사유는 보고서 입력에서 제외한다. 원본 JSON 감사 기록은 유지한다.
- 페이지나 근거가 예산으로 제거되면 남은 자료로 참조를 다시 만든다. 제거된
  원문을 가리키는 참조를 남기지 않으며, 실제 누락·부분 수록 경고는 유지한다.

## 보관 실행 검증

실행 `493e17fd-a964-4535-a068-35a8233b0589`의 읽기 전용 인덱스와 저장된 AI
응답 5개를 실제 `RetrievalAgent.run()`으로 재생했다. 같은 검색 결과 객체를
변경 전·후 `EvidenceBuilder` 및 `fit()`에 각각 넣었다. 의미 검색은 원래와
동일하게 활성화했고, 모델은 기존 로컬 캐시에서 로드했다. 새 외부 AI 호출과
보고서 재생성은 하지 않았다. 변경 전 결과는 저장된 원본의 크기·누락과 일치한다.

| 항목 | 변경 전 | 변경 후 |
|---|---:|---:|
| 최종 근거 패키지 | 97,096자 | 86,446자 |
| UTF-8 | 104,781 bytes | 93,622 bytes |
| 구성별 근거 | 8건 | 동일한 8건 |
| 수록 페이지 | 12쪽(부분 1쪽 포함) | 전문 14쪽 |
| 예산으로 제외한 페이지 | 2쪽 | 0쪽 |
| 부분 수록 | 1쪽, 741자 누락 | 0쪽 |
| 제외한 근거 / 패키지 축약 | 0건 / 0건 | 0건 / 0건 |

10만 자와 158,353 bytes의 기존 예산 안에서 빠졌던 두 페이지와 잘렸던
끝부분을 모두 담았다. 앞뒤 문맥을 포함한 구성별 근거 필드도 변경 전·후 동일하다.

검색 단계가 마지막 응답의 근거 확정을 이월 때문에 보류했던 사실은 별개다.
재생에서 미처리 요청은 0건이지만 검색 마무리의 라운드 상한 상태는 그대로
유지한다. 이 변경으로 미완료 검색을 완료로 바꾸거나 경고를 숨기지 않는다.
모든 크기의 자료가 무조건 예산 안에 들어간다는 보장이나 새 보고서의 판단 품질을
측정한 실험은 아니다.

## 앱 반영 상태

8765 서버의 실행·대기 작업이 모두 0건인 것을 확인했지만, 서버 종료·재시작
명령은 자동 승인 검토에서 정책상 차단됐다. 구체적인 사유는 반환되지 않았다.
코드는 저장됐으며 실행 중인 서버에 반영하려면 PRISM을 종료하고 다시 실행해야 한다.
