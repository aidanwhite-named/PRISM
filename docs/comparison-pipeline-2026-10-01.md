# 문헌별 구성 대비와 독립적인 판단 검토

사용자가 승인한 1~3번을 프로그램에 적용했다. 기존 실행의 보고서, 청구항, 문헌 매핑은 수정하지 않는다. 모델과 추론 강도를 바꾸지 않는다.

## 실행 순서

1. 청구항 원문에서 사용자 기호와 장치·방법의 전제부를 보존하고, 입력·동작·결과·조건을 해석한다. 사용자 후속 지시와 제공된 출원 명세서의 정의도 함께 전달한다. 명시되지 않은 속성과 의미 불확실성을 따로 기록한다.
2. 모든 인용문헌을 각각 읽고 원문 처리 흐름과 구성의 대응 범위를 정리한다. 자료 순서나 제목으로 주 문헌을 먼저 고르지 않는다.
3. 부분 대응·미발견·판단 불가 구성은 해당 문헌의 원문으로 다시 검토한다. 이전의 부정 결론은 재검토 입력에서 제외한다. 재검토 대상을 문헌별로 분리해 다른 구성의 판단이 섞이지 않게 한다.
4. 문헌별 실제 대응과 처리 관계를 비교해 주 문헌을 고른 뒤 보고서를 작성한다. 기존 고정 매핑이 있으면 유지한다.
5. 원문·발췌·구성 연결 검사 후, 구조 검사를 통과한 구성도 포함해 모든 구성의 기술적 판단을 독립적으로 검토한다. 선행 문헌별 판정표를 정답으로 전달하지 않는다.
6. 문제가 발견되면 별도의 재작성 단계에서 전체 보고서를 바로잡는다. 새 발췌의 연속 범위와 번역, 구성별 연결을 다시 검증한 결과만 반영한다.

기술적 대응은 모델이 판단한다. 프로그램은 같은 명칭이나 키워드를 정답으로 강제하지 않고, 실제 문언·기호·문헌 번호·원문 선택·근거 연결과 검토 완료 여부를 검사한다. 명칭이 다른 동등 기능을 배제하거나, 청구항에 없는 별도 모듈·특정 변수명·중간 단계 없는 직접 계산을 추가로 요구하지 않도록 각 단계의 지시를 맞췄다.

## 결과와 실패 처리

- 실제 전달한 문장 번호만 근거로 허용한다. 다른 문헌의 번호, 존재하지 않는 번호, 구성 누락, 긍정 근거 없는 대응 판단은 선행 검토 결과로 확정하지 않는다.
- 내부 구성 번호와 선정된 주 문헌의 표시 순서는 프로그램이 정리한다. 사용자의 청구항 기호와 기술적 판단을 변경하는 정리는 하지 않는다.
- Codex CLI의 `--output-schema`를 연결해 단계별 결과 형식을 제한한다. 유효한 JSON이 아닌 응답은 동일 입력으로 한 번 재시도하며, 재시도도 검증과 사용량 기록에 포함한다.
- 모든 구성의 검토 결과가 있어야 독립 검토를 완료로 처리한다. 발견한 문제에 대해 수정 결과가 없거나 새 원문·연결 검증이 실패하면 원래 결과를 보존하고 미완료 사유를 표시한다.
- 취소, 입력 한도, 도구 사용 탐지, 원문 선택 실패를 통과로 바꾸지 않는다. 검색 발췌만 제공된 경우의 미발견 판단은 그 제공 범위로 제한한다.
- 복수 문헌 대비, 잔존 차이만 한 줄로 표시, 발췌 중복 제거, 외국어 발췌의 짧은 확인용 원문 표시 규칙은 유지한다.

새 실행의 `comparison-review/audit.json`에 청구항 해석·문헌별 검토·미대응 재검토·주 문헌 선정이, `semantic-audit.json`에 전체 구성의 독립 검토·재작성·후속 발췌 검증이 남는다. 보고서 생성과 각 검토 호출의 사용량을 합산하면서 구분해서 저장한다. 추가 모델 호출 때문에 작성 시간과 사용량이 늘어난다.

## 검증

관련 백엔드 테스트 426개 통과. 문헌별 분리, 미대응 재검토, 입력 한도와 취소, 기호·원문 보존, 고정 매핑, 원문 번호 검증, 전 구성 검토 누락 차단, 별도 재작성, 연결·발췌 복구, 사용량과 실제 최종 입력 기록, 기존 보고서 형식 호환성을 포함한다.

실문헌 검증은 기존 실행 `65cd3b99-478a-4f4f-8525-2cf23050caf7`의 정규화 원문을 읽기 전용으로 사용했다. 모델은 기존과 같은 `gpt-6-luna`, 추론 강도는 `medium`이다. 사용자가 이 대화에서 명시한 D의 촬영 시각 시간 오프셋 해석을 검증 입력에 전달했다. 생성 결과는 `docs/artifacts/comparison-pipeline-20261001/`의 별도 검증 폴더에만 저장한다.

검증 과정에서 원문 문언 일부 생략, 전제부 누락, 요청하지 않은 구성 재검토, 주 문헌 목록 순서, 잘못된 응답 형식, 일부 구성만 검토하고 재작성을 생략하는 문제를 발견해 보강했다. 기술적 대응과 주 문헌 선정에 모델의 판단 변동이 남으며, 이 수정이 항상 같은 결론이나 판단 정확성을 보장하지는 않는다.

최종 실문헌 검증 `live-replay-v8`은 검증된 선행 문헌별 검토 결과를 재사용하고, 원문 전체를 독립 검토에 다시 전달했다. 모든 5개 구성을 검토하여 불일치 8건을 발견하고 별도 재작성과 구성 연결 복구를 완료했다. 최종 `semantic_review` 상태는 `corrected`, 구조·원문 연결 점검 항목은 0개다. 주 문헌은 ATT-01을 유지한 것으로, ATT-03을 선호한 앞선 직접 검토와 선정 판단까지 일치한 결과는 아니다.

실행 중 분석이 없는 것을 확인한 뒤 기존 PRISM 데이터 폴더를 유지하며 8765·8766·8767 서버에 최종 수정을 적용했다. 세 서버의 상태 확인 응답이 정상이다. 기존 보고서를 수정하거나 검증 결과로 교체하지 않았다.
