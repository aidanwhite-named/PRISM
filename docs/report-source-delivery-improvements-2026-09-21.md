# 원문 전달과 구성별 판단 개선

## 적용 내용

자동 전달은 모델 입력 한도 안에 들어가는 전체 추출 원문을 우선한다. 기존에는
Codex 모델 한도를 확인하지 않아 128,000 토큰 대체값을 사용하고, 한국어 입력을
UTF-8 바이트/2로 크게 추산하여 들어갈 수 있는 문헌도 검색 방식으로 전환했다.

이제 명시적 모델 한도 설정을 우선하고, 없으면 Codex CLI의 `models_cache.json`에서
정확히 일치하는 모델의 기본 컨텍스트와 유효 비율을 읽는다. 별도 설정이 필요한
`max_context_window`는 사용하지 않는다. 확인할 수 없는 모델은 기존 대체값을 유지한다.
지원하는 Codex GPT-5 계열은 로컬 `o200k_base` 토큰 수에 5%와 16,384 토큰을 더하며,
출력·추론 예약은 별도로 뺀다. 이는 CLI 전체 토큰의 정확한 상한 보장이 아니다.
[OpenAI 토큰 계산 문서](https://developers.openai.com/api/docs/guides/token-counting)도
로컬 텍스트 계산과 전체 요청 계산을 구분한다.

설치 시 토크나이저 캐시를 준비하고 해시로 확인한다. 실행 중 사전 검사는 캐시를
읽기만 하며, 라이브러리·캐시가 없거나 손상되면 기존 바이트 추정으로 돌아간다.
전송 하드 한도, 명시적 전달 모드 및 사용자가 켠 규모 기준은 계속 적용된다.

검색이 필요한 큰 문헌에서는 관련성 메모·최종 검색 메모·중요도·불확실성을 보고서
입력에서 제외한다. 해당 값은 감사용 JSON에 보존한다. 검색 모델이 최종 근거로
선정하지 않은 실제 검색 후보도 구성·문헌을 번갈아가며 추가한다. 추가 원문은
근거 문자 예산의 최대 1/4로 제한하며 최종 문자·바이트 한도를 다시 검사한다.
예산으로 생략한 후보 수를 기록하고, 임의 후보를 의미 대응으로 확정하지 않는다.
검색된 적 없는 추측 chunk ID나 모델이 쓴 발췌 문장은 원문으로 전달하지 않는다.

기본 보고서 프롬프트는 다음을 구분하도록 정리했다.

- 개별 구성의 한정과 전체 청구항의 결합·순서 조건.
- 제1/제2 등 명칭과 대상의 실제 역할·기술 관계.
- 종속항의 추가 한정과 인용한 선행항의 구성. 기존 선택 발췌에 검색을 제한하지 않는다.
- 원문으로 입증해야 하는 기술적 사실과 그 사실에 근거한 분석자의 도출·결합 추론.
- 자료 검토 범위의 부족과 제공된 원문에서 확인할 수 있는 부분 대응.

중복되는 문장 틀을 줄이고 전체 청구항의 관계와 잔존 차이를 종합 분석에 모았다.
기존 보고서를 덮어쓰지 않으며 새로 생성한 보고서부터 변경된 프롬프트를 사용한다.

## 동일 사례 검증

기존 실행: `90f45296-266e-460e-af4a-d49896166967`.
첫 개선 검증 실행: `beae3e72-564a-4cdc-913b-dc099c1efc75`.
두 PDF 85쪽, 동일 청구항, 동일 Codex `gpt-5.6-luna`를 사용하고 첨부만 재사용했다.

새 preflight는 `full_inline`을 선택했다. 안전 여유 포함 예상 입력은 155,602 토큰,
CLI 카탈로그 유효 컨텍스트는 258,400 토큰, 출력 예약을 뺀 입력 예산은 226,400 토큰이다.
실제 `final_prompt.txt`에 [0323] 스트림 교체, [0160] 사전 준비 및 구매·결제 관련
원문이 포함되며 검색 AI 메모는 없다. 변경한 마스터 프롬프트 스냅샷도 확인했다.

첫 검증은 150.7초에 정상 완료되었다. 실제 입력 사용량은 144,247 토큰으로,
여유를 포함한 추정치보다 작았다. 보고서는 [0323]의 기존 스트림 교체와
[0070]~[0072]의 구매·결제를 활용했고, [0160]의 사전 준비도 분석했다.
다만 G의 차이점에 D의 시간 조건을 가져오고 구성 문장을 요약하는 문제가 남아,
구성 원문을 보존하고 차이의 요구가 어느 구성에서 나오는지 확인하도록 추가 정리했다.
최종 프롬프트 검증 실행은 `e723f000-8063-49cf-8c1c-d1c1dc06885e`이다.
이 실행에서도 두 정규화 원문 196,094자와 27,473자가 각각 통째로 입력에 포함됨을 확인했다.

최종 검증은 126.7초에 정상 완료되었고 실제 입력 사용량은 144,368 토큰이다.
7개 구성을 모두 생성했으며, D의 인수 요청에 대한 응답·단절 전 조건과 G의
제2 스트림에 기초한 방송 제공 관계를 구성 원문에 보존했다. 문헌 발췌를
본문에 제시했고 [0323], [0160], 구매·결제 기재를 활용했다. F에서는 제2라는
명칭 부재를 차이로 취급하지 않았다.

한계도 남았다. G의 설명에서 E의 상거래 세션 유지 조건까지 다시 논의하고,
일부 보조 문헌 설명에도 현재 구성 외의 인수 조건이 섞였다. 명시적 기재와
기술적 추론을 가르는 판단도 일관된 정답으로 검증된 것은 아니다. 이 결과는
원문 누락과 입력 경로 개선을 확인한 사례이며, 프롬프트만으로 모든 구성대비
판단 오류가 제거됐다는 증거로 취급하지 않는다. 이를 막겠다며 모델 점수를
코드로 고치거나 보고서를 다시 조립하는 처리는 추가하지 않았다.
