# 인용·피인용 검색 연결 및 입력 화면 정리

## 화면

유사문헌 검색의 검색 전략 선택란 및 준비 상태의 전략 이름을 숨겼다. 기본 검색 지침은 설정에서 계속 적용하고 실행 기록에 보존한다. 검색 깊이는 오른쪽 명세서·기준일 패널에서 **검색 준비의 청구항 입력칸 위**로 옮겼다. 빠른/심층/정밀 선택이 동일한 `search_depth` 요청값으로 전달된다.

## 자동 검색 순서

관계 중심 검색·검증에서 X 미확인 → 기존 특허·논문 후보 검색 → 관련 seed의 인용·피인용 조회 → 후보 합집합 → 순위 선정·원문 검증 → 남은 예산에 따른 확장.

원문 근거를 갖춘 X가 이미 있으면 인용 조회를 시작하지 않는다. 조회할 식별 가능한 관련 후보가 없거나, 시간·질의·원문·LLM 예산이 부족해도 생략하며 사유를 기록한다. 초기 구현은 기존 후보 검증 후 조회했으나 실험에서 예산 소진으로 생략되어, 후보 수집 직후 조회하여 다음 검증에 합치는 순서로 바꿨다. 별도 인용 검증 LLM 호출을 매번 추가하지 않는다.

- 특허: EPO biblio의 patcit에서 직접 인용 번호를 추출하고, 피인용은 `ct` 검색. [EPO 공식 설명](https://www.epo.org/en/service-support/faq/searching-patents/open-patent-services/search-queries-tips-and-tricks/how-do-i)
- 논문: OpenAlex의 `cited_by`(참고문헌)와 `cites`(피인용) 필터. 기존 하위 계층에도 제한적인 피인용 조회 보조 기능은 있었으나 자동 엔진 경로에는 연결되지 않았었다. [OpenAlex 공식 필터 문서](https://github.com/ourresearch/openalex-docs/blob/main/api-entities/works/filter-works.md)
- 한 요청에서 특허 seed 1건과 논문 seed 1건까지, 한 단계만 추적한다. 남은 질의 수가 작으면 seed 수를 줄여 양방향 조회를 우선한다. 원문 검증을 위해 25초를 남기고 인용 조회는 최대 30초다.
- 특허 참고문헌은 정확한 식별자 최대 3건의 서지를 조회한다. 특허 피인용과 논문 양방향은 각각 첫 20건까지다. 누락·총 결과 수·실패·전환을 기록한다. 인용 연결 자체는 관련성 또는 X 판정이 아니다.
- 공개일 조건은 문헌별로 유지한다. 기준일 이후 문헌을 검증 대상으로 승격하지 않는다. 초록은 전문으로 취급하지 않는다. 출처 원본과 seed→candidate 방향을 `citation_edges` 및 검색 로그에 보존한다.

## 실제 조회

EP4386678A1의 직접 인용은 US2012075342A1, US10992947B2 두 건이었다. 피인용 조회는 0건이었다. 첫 구현에서 번호 검색이 US10992947B2 대신 US2020413080A1을 반환했다. 대응 공개문헌을 직접 인용문헌으로 오인하지 않도록 정확한 번호의 biblio 조회로 수정했고, 최종 조회에서 두 식별자를 확인했다. EPO 인용 조회 0건은 다른 데이터베이스에도 피인용이 없다는 뜻이 아니다.

논문 DOI `10.1109/tcsvt.2016.2543039`는 참고문헌 19건, 피인용 총 432건 중 첫 20건을 조회했다. API 원본 및 실행 결과는 `%LOCALAPPDATA%/PRISM/diagnostics/citations-20260917/`에 보존했다.

Gaussian 회귀 청구항 통합 실행 `a1086a20-5e96-44f8-94fa-4951f53c94af`:

- 관계 검색에서 X 미확인 후 기존 후보 및 인용 조회로 진입했다.
- 인용 단계 5.563초, CN122435109A와 논문 DOI `10.48550/arxiv.2308.04079`를 seed로 양방향 조회했다.
- 논문 피인용 20건이 새 후보로 합쳐졌다. 전체 후보 63건, 전체 실행 99.578초, 전문 확보 문헌 1건이었다.
- 이 실행에서 X는 확인하지 못했다. 평가에 등록한 두 부분 관련 문헌도 상위 20건에 없었다. 따라서 이번 실험은 자동 경로와 후보 추가의 동작 확인이며, 검색 품질 개선을 입증하지 않는다. 질의 캐시 적중 6건 및 계획 캐시 사용이 있어 이전 실행과의 속도 비교도 통제된 실험이 아니다.

## 검증

관련 백엔드 테스트 224개, 화면 테스트 9개 및 프런트엔드 빌드 통과. 정확한 인용 번호 보존, 다른 문헌/출원번호 혼입 방지, 방향별 필터, X 확인 시 호출 생략, 예산 부족 시 생략, 기준일 이후 후보 배제, 별도 LLM 호출 없이 기존 검증에 합치는 순서를 확인했다.

남은 한계: 인용 데이터 누락·시차, 첫 페이지 제한, 지원 식별자 없는 논문(arXiv ID만 있는 후보 등), seed 선정 및 검색어 품질, LLM 관계 판정 변동. 원문 검증용 예산을 늘리려면 사용자는 검색 깊이에서 정밀 검색을 선택할 수 있다.
