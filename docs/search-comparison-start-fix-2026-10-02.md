# 검색 문헌 구성대비 시작 표시와 재실행 수정

검색 `d0fe0973-4ed6-4e6a-8bb3-46df5e0d8f22`에서 선택한 두 문헌으로 분석 `c042008a-85bd-4de8-b4f6-fd803975167c`가 실제 생성됐으나 검색 화면에 머물렀다. 이 분석은 출원발명 자료 ATT-01을 인용문헌에 넣은 모델 응답 때문에 INVALID_OUTPUT으로 실패했다. 같은 선택을 다시 제출해도 기존 실패 작업을 반환해 새 분석을 시작할 수 없었다. CATSplat은 검색에서 확보한 arXiv HTML 본문이 구성대비 단계에서 인식되지 않아 보류됐다.

## 변경

- 문헌 확보 중 버튼 아래 진행 안내를 표시하고, 작업이 만들어지면 `/analysis?job=…`로 이동한다. 본문을 하나도 확보하지 못하면 검색 화면에서 보류 사유를 보여 준다. 기록 갱신은 요청 완료 후 수행한다.
- 같은 문헌의 대기·진행·성공 작업은 재사용한다. 실패·취소 작업은 새 분석을 만들 수 있게 하며 이전 기록을 보존한다.
- 자료 역할에 따라 실제 인용문헌으로 허용되는 ATT 번호와 출원발명 자료 번호를 분석 입력에 명시한다. 인용발명 순번과 ATT 번호를 구분하도록 안내한다. 출원발명 자료를 인용문헌으로 받지 않는 기존 검증은 유지한다. 이 안내가 모델의 모든 형식 오류를 방지한다는 의미는 아니다.
- 검색의 `full_text` 원 응답 캐시도 재사용한다. arXiv의 식별 가능한 논문 HTML 본문은 기존 검색 본문 파서로 추출해 텍스트 첨부로 전달한다. 초록·일반 페이지와 다른 문헌 번호는 보류하고, 도면 이미지 제외 범위를 표시한다.

## 검증 및 적용

백엔드 관련 테스트 38개와 화면 관련 테스트 21개 통과. 실제 선택 문헌의 검색 원 응답을 임시 폴더에 재사용하는 검사에서 CATSplat HTML 본문 56,728자와 Sketch and Text Guided Diffusion 논문 PDF 텍스트 54,992자를 확보했다. 추가 모델 실행 없이 본문 전달 경로를 확인했다. 프론트엔드 빌드와 변경 파일 공백 검사 통과.

진행 중이던 사용자 분석 `f95331f7-dade-4178-b8b2-4c846217b2f8`가 SUCCEEDED로 끝난 것을 확인한 뒤 8765·8766 서버를 재시작했다. 두 서버의 상태 확인과 기존 분석 기록 조회가 정상이며 데이터 폴더는 유지했다. 기존 실패 보고서를 새 결과로 교체하지 않았다. 새 모델 분석의 결과 품질은 재실행 후 확인해야 한다.
