# 유사문헌 검색 검증 보완

2026-09-05 최신 검색은 웹 검색 3회 뒤 종료했고 원문 조회가 없었다. 네 후보의
구성 대응 근거 9개가 모두 미검증인데도 manifest가 complete였다.

## 변경

- 검색 실행 상태와 근거 검증 상태를 quality에 따로 기록한다. 후보의 서지·근거가
  미확인인 정상 종료는 manifest의 verification_incomplete 상태로 표시한다.
  Job의 SUCCEEDED는 CLI 실행 성공이며 보고서와 감사 화면에는 검증 미완료를 표시한다.
- 검색 범위의 충분성은 기계적으로 입증하지 않는다. search_coverage는
  not_established이며 빈 후보도 검색이 충분했다는 증거로 취급하지 않는다.
- 보존된 공식 응답의 식별자·제목·저자/출원인·공개일·대응 근거를 대조한다.
  제목이나 저자 표기의 차이는 오류 확정이 아닌 확인 사항이다. 번역·약칭도 차이가
  날 수 있으므로 보존 응답 값과 모델 값 모두 남긴다.
- 첫 출력에 미검증 후보가 있으면 같은 Provider와 입력으로 추가 사실 확인을 최대
  한 번 요청한다. 남은 전체 시간과 도구 호출 예산을 사용한다. MCP 원장은 최초 실행과
  공유한다. 입력 크기가 한도를 넘거나 취소·예산 소진이면 추가 요청하지 않는다.
- 추가 출력은 전체 후보 식별자·순서·group이 유지될 때만 채택한다. PRISM이 후보를
  재선발하거나 기술적 분류를 수정하지 않는다. 추가 출력 오류나 후보 변경이면 최초
  후보를 유지하며 새 호출 기록으로 다시 기계 검증한다.
- 추가 실행의 취소·시간 초과·정책 위반을 최초 실행 성공으로 덮지 않는다. 실패한
  추가 실행의 판정을 보존한다. 최초 출력, 추가 프롬프트·출력·사용량은 별도 아티팩트로
  남긴다. 원시 stdout/stderr 저장은 기존 keep_raw 설정을 따른다.
- 미시도, 조회 후 미해결, 호출 실패, 호출 결과 미확인, 연결 미지원, 한도 소진을
  구분해 보고한다. 한도 소진은 실패 기록/Provider 신호로 판정하며 짧은 실행 시간이나
  후보 수만으로 추정하지 않는다.

## 확인 범위와 제한

검색 API·출력 계약·도구 정책·추가 조회 예산/실패·화면 표시 회귀 테스트와 프론트엔드
프로덕션 빌드로 확인했다. 기존 저장 실행이나 원본 보고서는 수정하지 않았다.
외부 CLI를 통한 실제 재검색은 이 변경의 테스트에 포함하지 않았다.

agy의 실행별 MCP 연결 미지원과 Kiwee 접속 미구현은 별개 제약이다. 웹 원문을 읽어도
보존된 공식 필드 근거가 없으면 검증 완료로 승격하지 않는다. 추가 조회를 수행한다는
사실만으로 근거 검증 완료나 충분한 검색을 보장하지 않는다. 실행 중인 서버에는 재시작이 필요하다.
