# 마지막 보고서의 기호·근거 연결·점수 불일치 수정

대상 실행: `a7ec49ea-7bab-421d-8321-b3c79f68aee9`.

원문 8개는 모두 검증됐지만, 전제부의 빈 기호와 A/B/C의 주 문헌 근거·점수 불일치 때문에 점검 오류 5건이 발생했다. 외국어 표시 발췌 축약이나 원문 소실이 원인은 아니었다.

- 빈 기호는 사용자 기호를 바꾸지 않는 자동 구분 표시로 처리한다. 원 응답과 정규화 기록을 함께 보존한다.
- 명시된 검증 근거 ID의 연결 누락은 복원하되 문헌명만으로 연결을 추정하지 않는다. 출력 중복 제거와 구성별 근거 연결을 구분하도록 생성 지침을 보완했다.
- 주 문헌 미발견이면 점수 0, 판독·판단 불가이면 null임을 지침과 검증에 반영했다.
- 남은 연결·점수 모순은 기존 검증 발췌로 해당 구성만 제한적으로 재검토한다. 잘못된 연결·새 근거·다른 구성 변경은 거절하고 해결하지 못하면 기존 점검 표시를 남긴다.

실제 재검토는 기존 실행과 같은 모델·추론강도로 1회 수행했다. A에는 기존 E1을 연결하고 인용발명 1 기준 점수를 60→25로 재평가했다. B/C는 기존 주 문헌 미발견 판단에 맞춰 각각 10→0, 55→0으로 교정했다. 인용발명 2의 대응 근거는 유지했다. 전제부와 D의 점수는 유지됐다. 문헌 매핑·청구항 문언·원문 8개·번역은 변경하지 않았으며 점검 오류는 0건이다. 모델 재평가와 형식 검증의 결과이지 기술적 정확성을 자동으로 보증하는 것은 아니다.

재현 및 교정본은 `artifacts/report-component-consistency-20260930/`에 있다. 적용 시 원 DB 필드와 결과 파일을 해당 실행의 `report-component-consistency-20260930/original/`에 백업하고 원 `analysis-response.txt`는 그대로 보존한다.

검증: 관련 테스트 257개 통과. 실제 교정본을 저장 실행에 반영했고, 진행 중인 작업이 없음을 확인한 뒤 8765/8766 서버를 재시작했다. 두 서버의 API에서 정상 상태, 구성 5개, 점검 오류 0개, 교정 완료 상태를 확인했다. 원 응답과 발췌·번역은 보존됐으며 교정 호출의 사용량도 별도 집계했다.
