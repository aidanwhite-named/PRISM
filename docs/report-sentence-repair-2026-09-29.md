# 문장 선택 자동 복구 적용

구조화 보고서 V3의 원문 문장 선택이 검증되지 않을 때만 복구한다. 해당 문헌의 실제 전달 원문 전체 조각과 고유 문장 번호를 다시 제공하고, 실패한 E번호의 sentence_ids·language·translation만 요청한다. 보고서 전체를 다시 쓰거나 점수·문헌 매핑·구성·대응 판단을 변경하지 않는다.

최대 2회·총 180초이며, 호출마다 문자/바이트/모델 입력 한도를 적용한다. 예산이 부족한 자료는 잘라서 성공으로 처리하지 않는다. 같은 문헌·같은 원문 조각 안의 연속된 문장이고 기존 검증을 통과한 항목만 채택한다. 정상 근거는 그대로 유지한다. 실패·시간 초과·취소 시 확인 가능한 결과를 보존하고, 남은 근거 오류는 보고서 맨 위에 미완료로 표시한다. 원문 일치 검증은 번역과 기술적 대응의 의미적 정확성까지 보증하지 않는다.

원 응답과 복구 입력·응답·검증 기록·채택 JSON을 분리 보존한다. 추가 토큰은 기존 최종 생성 사용량에 합산하고 sentence_repair에 분리 기록한다. 검색 사용량은 종전처럼 retrieval에 별도 기록된다. 자동 복구는 다음 보고서 생성부터 적용되며 기존 저장 보고서는 자동 수정하지 않는다.

검증: test_report_repair.py, test_structured_report.py, test_report_sources.py, test_prompt_assembly.py, test_report_source_delivery.py 총 156개 통과. 전체 전달과 RAG, 같은 페이지의 복수 원문 조각, 잘못된 문헌·역순·없는 번호, 정상 근거/점수 변경 시도, 입력 제한, 호출 실패·금지 도구·시간 초과·취소, API 실행과 기록 저장을 확인했다.

최근 실행의 저장 근거 묶음에서도 재생성한 고유 문장 번호 517개가 실제 전달 프롬프트와 정확히 일치했다. 검증에는 실제 모델 호출을 사용하지 않았다. 8765 포트의 로컬 서버를 재시작하여 적용했고 health API의 정상 응답을 확인했다. 검색 라운드와 근거 분량 설정은 변경하지 않았다.

최근 실행 사용량은 검색 7회 251,858토큰, 최종 생성 73,258토큰, 합계 325,116토큰으로 기록됐다. thinking_tokens를 total_tokens에 다시 더하지 않았다. 캐시 및 서비스 과금 방식이 반영된 실제 요금 계산은 하지 않았다.
