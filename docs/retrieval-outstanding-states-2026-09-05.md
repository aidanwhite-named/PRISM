# 검색 상태·반복 전달 변경 정정 — 2026-09-05

이 문서는 앞선 outstanding/회차 간 생략 구현 설명을 대체한다.

후속 실제 재생에서 구성별 잔액 분할의 열람 정체가 확인되어 배분 방식을 다시
단순화했다. 최신 배분·검증은 [페이지 열람 진행 기록](retrieval-read-progress-2026-09-05.md)을 따른다.

## 수정 결과

- 배타적 `outstanding` 상태, 상태별 추가 우선순위, next_step 전송 캐시를 제거했다.
  페이지 하나를 열람했다고 구성 전체를 resolved로 표시하지 않는다.
- 기존 searched_documents, unsearched_documents, deferred_actions,
  reviewed_pages, unreviewed_pages 및 패키지 page_reductions/page_truncations 기록을
  유지한다. 상태 머신을 추가하지 않고 서로 다른 누락 사실을 기존 기록으로 확인한다.
- 문헌 서지·추출 상태, 구성 정의, 후보 발췌, 앞뒤 문맥의 회차 간 생략을 제거했다.
  호출마다 필요한 입력을 보내며, 같은 호출 안의 원문 중복 제거와 압축 JSON은 유지한다.
- 검색어 절반 기준의 유사 검색 유보와 별도 판단 함수를 제거했다.
  기존 검색 캐시, 고정 후보 목록, 이월 큐와 재시도 경로는 유지한다.
- 30% 예약 몫과 action당 최소 4,000자 규칙을 제거하고 구성별 잔액을 사용한다.
  최초 몫을 구성 수로 나누고 실제 직렬화 크기를 차감한다. 구성 내부에서는 남은
  action 수로 나눈다. 해당 구성의 마지막 action 후 남은 몫은 이후 구성에 재배정한다.
  이미 지나간 action을 같은 회차에 다시 도는 추가 재처리 루프는 만들지 않았다.
- 회차 수, 반환 문자, 페이지, 최종 패키지 상한과 의미 검색 설정은 변경하지 않았다.

## 검증 범위

회귀 검증은 다음을 확인한다.

- 한 구성에 20개 요청이 있어도 다른 구성의 몫을 침범하지 않는다(양쪽 순서).
- 끝난 구성의 미사용 예산을 뒤의 작업에 사용할 수 있다.
- 5회차까지 문헌 상태·구성 정의·후보 발췌를 유지한다.
- 대응 해석을 뒤집을 수 있는 부정·제약 문맥이 반복 검색 후에도 남는다.
- 기존 검색·이월·페이지 열람·API·보고서·근거 보존 회귀 검증.

앞서 기록한 −9.8%는 결정적 가짜 provider의 입력 문자 감소였다. 실제 LLM 토큰
절감이나 판단 품질 보존을 입증하지 않았으며, 제거한 문맥 생략 방식의 결과이므로
현재 구현의 성능 수치로 사용하지 않는다. 실제 LLM 보고서를 재생성하지 않는다.
