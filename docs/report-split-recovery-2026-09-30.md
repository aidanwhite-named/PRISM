대상 실행: `7b7bb6c4-fac4-4524-8eb2-0be3e8290541`.

## 원인

이번 실행은 Codex `gpt-5.6-luna`의 `full_inline` 경로였다. 검색 라운드나 RAG
예산 소진이 아니라, 보고서 출력과 자동 교정의 형식 제약 때문에 인용이 가려졌다.

- E1은 같은 페이지의 T5–T8과 T10–T12를 하나의 발췌로 선택했다.
- E3, E4, E6도 떨어진 구간을 하나의 근거로 묶었다.
- 연속 원문만 직접 인용하도록 하는 검증기가 이 네 항목을 거절했다.
- 교정 모델은 각 근거를 두 구간으로 나누고 구간별 번역을 반환했다. 첫 응답은
  동일 부모 ID를 반복했고, 두 번째 응답은 E1-1/E1-2 등의 분할 ID를 사용했다.
- 교정 코드는 요청한 4개 근거보다 많은 8개 항목을 반환했다는 이유로 두 응답을
  모두 거절했다. 분할 근거를 구성·차이점에 다시 연결하는 처리가 없었다.
- 구성 C가 사용하는 E1·E3·E4가 모두 실패하여 원문 발췌가 표시되지 않았다.
  대응 이유와 잔존 차이의 서술은 있었지만, 인용 연결은 확인 미완료 상태였다.

보고서 생성 입력은 110,189토큰, 실패한 교정 두 번의 입력은 각 51,370토큰이었다.
교정 입력 제한으로 차단된 항목은 없고, 실패 원인은 응답 형식 검사였다.

## 수정

`report_repair.py`가 부모 근거 아래의 `segments`를 받아 각 구간의 원문과 번역을
검증하고, 새 E번호를 할당하여 구성·차이점·보완 문헌의 근거 목록을 함께 갱신한다.
기존 교정 응답의 동일 ID 반복 및 E1-1 형식도 엄격한 분할 검증을 거쳐 지원한다.

분할은 원래 선택한 문장들의 순서와 범위를 정확히 보존해야 한다. 중간 내용을
채워 넣거나, 선택 일부를 삭제하거나, 다른 문헌을 가져와 통과시키지 않는다.
각 부모의 모든 구간이 검증되어야 적용한다. 점수·대응 이유·차이 판단·문헌 매핑은
변경하지 않으며, 유효했던 근거도 그대로 둔다.

문장 ID가 유효하고 분할만 필요한 경우에는 프로그램이 예상 분할을 만들고 해당
원문만 교정 입력에 넣는다. 알 수 없는 ID는 기존 문헌 범위 내 재선택 경로를 유지한다.
교정 재시도에는 직전 거절 이유를 제공한다. 사용량 합산에 캐시·추론 하위 집계도 반영한다.
