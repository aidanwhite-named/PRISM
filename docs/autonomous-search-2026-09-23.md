# 유사문헌 자율 검색 구조 변경

신규 유사문헌 검색은 `search_engine/autonomous.py`의 단일 Provider 실행으로 진행한다. 프로그램은 전체 제한시간, 입력 범위, 출처 기록과 결과 저장을 관리하며 검색어·검색 순서·확장·원문 확인·후보 선택은 모델이 결정한다.

- 단계별 계획/선별/분류/검증 모델 호출을 신규 실행에서 제거했다.
- X/Y/Z 분류 의무, 후보 개수, 도구 호출 횟수, 단계별 시간 배분 및 분류용 예약시간을 제거했다.
- 검색 도구 응답의 기존 4건 강제 축소와 초록·본문의 고정 길이 축약을 신규 경로에서 제거했다. 출처 API의 요청별 페이지 크기, 통신 한도 및 계정 쿼터는 그대로 적용된다.
- 명세서를 별도로 잘라 전달하지 않는다. 모델 서비스의 입력 전송 한도를 넘는 경우에는 명시적으로 알린다.
- `save_findings`는 제목·URL·관련성 이유를 중간 저장한다. 개수 제한 없이 모델의 순서를 유지하며 출처 식별자와 URL의 일치 여부를 확인한다. 원문 열람 기록과 모델이 주장하는 확인 범위는 구분한다.
- 시간 종료와 사용자 중단 때 저장된 후보 및 출처 기록을 보존한다. 별도 분류 실행을 추가하지 않는다.
- 설정의 `search_timeout_seconds`가 실행 전체 제한시간이다. 기본값은 300초다. 사용자가 검색을 이어가면 이전 후보를 전달하고 같은 설정의 시간을 새로 부여한다.
- 옛 실행 모듈 21개와 진단 스크립트 3개를 삭제했다. `progressive_search_enabled`, 단계별 예산, 도구 호출 및 상세 조회 횟수, 출처별 누적 통신시간 제한과 관련 설정도 삭제했다.
- 과거 결과 표시는 `search_history/`와 화면의 `search-history/`로 분리했다. 출처 조회는 `search_source_tools.py`, 원문 해석·인용 조회·저장은 독립 모듈로 남겼다. 저장된 과거 분류는 읽기만 하며 새 검색에서 실행하지 않는다.
- 검색 프롬프트는 사용자 선택을 유지한다. 기본 전략은 구성 사이의 관계와 전체 기술적 내용을 고려하되 검색 방법과 출력 형식을 강제하지 않는다.

입력 사전 확인과 실제 실행은 동일한 입력 조립 함수를 사용한다. 미대응 구성 검색도 원본 청구항과 선택한 구성만 전달한다. 구성대비 분석의 실행과 보고서 프롬프트는 별개다.

검증: 단일 실행, 호출·후보 제한 제거, 긴 명세서 전달, 출처 기록, 시간 종료·중단, 저장 실패, 이어가기, 설정과 실행 입력 일치, 기존 분석 회귀를 자동 테스트한다. 실제 서비스 검증용 `backend/scripts/validate_autonomous_search.py`는 별도 validation 폴더에 결과를 저장하며 사용자 작업 이력을 생성하지 않는다. 실제 검색 성공은 확인했지만, 이전 방식보다 검색 품질이 높은지는 동일 청구항을 이용한 별도 비교가 필요하다.

초기 전환 검증 결과(옛 모듈 삭제 전):

- 백엔드 전체: 1,599개 통과, 기존 실패 3개, 실제 CLI 전용 16개 제외. 실패 3개는 수정 전 HEAD를 별도 폴더로 추출하여 같은 실패를 재현했다(근거 묶음의 이전 AI 판단 표시 기대, 구형 키프리스 페이지 크기 기대, 구형 국내 검색 순서 기대).
- 최종 저장·전송 보완 후 자율 검색 테스트 16개 통과. 실제 MCP 전송으로 64KB가 넘는 후보 130건 저장도 확인했다.
- 화면 테스트 132개 통과, 화면 빌드 성공.
- 실제 Codex 검색: 90초 제한, 약 90.1초에 종료, 문헌 6건과 출처 기록 보존, 별도 분류 호출 없음.
- 로컬 서버 정상 실행, 설정 및 실행 전 확인에서 300초와 자율 검색 경로 확인.

옛 모듈 삭제 후 확인:

- 2026-09-28 최종 관련 검사 268개 통과. 실행 중인 서버의 상태 응답 `ok` 확인.
- 검색·출처 및 실행기 관련 검사 352개 통과 후, 남은 두 테스트의 옛 도구 이름·오류 문구 기대를 갱신했고 해당 검사 36개가 통과했다.
- 화면 검사 132개 통과 후 폐기된 설정의 중복 사례 하나를 제거했고, 최종 화면 빌드가 성공했다.
- 실제 검색은 60초 제한에서 57.8초에 완료되어 문헌 4건과 출처 기록을 저장했다.
- 전체 검사에서 남은 옛 계약 기대를 정리했다. 근거 묶음에 이전 AI 판단 문구가 포함되기를 기대하는 실패는 변경 전에도 재현된 별도 문제다.

토큰 사용량: 전체 시간은 검색이 계속되는 기간을 제한하며 총 토큰 수를 보장하지 않는다. 한 검색 세션에도 여러 도구 호출과 모델 응답이 포함된다. 원문 재조회 캐시는 통신을 줄이지만 같은 본문을 모델에 다시 보내면 입력 토큰이 발생할 수 있다. 일부 실행기는 종료 후에 사용량을 보고하므로 엄격한 공통 토큰 상한은 별도의 예산 제어가 필요하다. 이번 변경에는 토큰 상한을 추가하지 않았다.
