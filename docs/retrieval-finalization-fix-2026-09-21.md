# 근거 확정 응답 누락 수정

대상 실행: `34d13484-560d-4424-b88b-1dd50003dab0`.

마지막 검색 응답이 근거 13건을 `actions[].finalize_evidence`가 아니라
최상위 `components`에 넣었다. 정확한 계약은
`{"actions":[{"action":"finalize_evidence","components":[...]}]}`이다.
기존 파서는 이를 구성 선언으로 읽으며 근거 필드를 무시했고, 에이전트는
유효한 확정 없이도 근거 패키지와 보고서 생성을 진행했다.

## 변경

- 최상위 구성 선언에 근거 확정 필드가 있으면 명시적인 파싱 오류로 돌려준다.
- 마지막 검색 라운드에서 형식 오류, 확정 누락, 구성 목록 오류가 발생하면
  교정 전용 호출을 최대 한 번 추가한다. 마지막 호출에 제공했던 검색 결과,
  잘못된 응답, 오류 설명을 전달하며 새 검색·열람은 실행하지 않는다.
- 교정에도 실패하면 `RETRIEVAL_FAILED`로 중단한다. 서비스는 실패한 실행의
  근거 패키지를 만들거나 최종 보고서 단계로 넘기지 않는다.
- 교정 호출에도 취소, Provider 전송 크기 검사, 호출 시간 제한과 사용량·입출력
  기록을 적용한다. 설정한 검색 라운드 수 외에 교정 호출이 한 번 추가될 수 있다.
- 정상 확정 및 실제로 찾지 못했다고 유효하게 확정한 응답은 기존대로 처리한다.

이번 변경은 응답 형식 처리에 한정된다. 청구항 1의 기존 대비 결과 상속이나
종속항 검색 범위 변경은 포함하지 않는다. 기존 보고서와 실행 기록도 보존한다.

## 검증

실패한 실제 저장 응답을 새 파서에 입력했을 때 명시적인 형식 오류로 거절됨을
확인했다. 자동 테스트에서는 잘못된 위치, 확정 누락, 잘못된 JSON, 구성 누락의
교정 성공·실패를 각각 확인한다. 교정 시 기존 원문 보존, 추가 검색 금지,
최대 한 번의 교정, 실패 시 패키지 미생성, 정상 확정 시 추가 호출 없음도 검증한다.
외부 모델을 호출한 재실행은 수행하지 않았다.

관련 테스트 189개 통과. 함께 실행할 때 fixture 등록 문제로 초기화되지 않은
`test_delivery_integration.py`는 별도로 실행하여 9개 모두 통과했다(합계 198개).
진행 중인 작업이 없는 것을 확인한 뒤 로컬 서버를 재시작하고
`/api/health`의 정상 응답을 확인했다.
