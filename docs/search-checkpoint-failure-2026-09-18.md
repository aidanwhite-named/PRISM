# 유사문헌 검색 후보 저장 실패 진단 및 수정

## 실제 원인

실행 `bb4d9d34-b958-4584-96f3-63d8d13ef0af`는 2026-09-18 16:54:48 KST에 시작한 `similarity_search` 작업이다. 모델은 `codex / gpt-5.6-luna`다. 16:55:28 후보 5건을 저장하려다 `SEARCH_CHECKPOINT_FAILED`로 종료됐다.

검색 도구 원시 기록에는 `SearchLogError: 후보 5: group은 A/B/C/null이어야 합니다.`가 남아 있다. 다섯 번째 후보의 분류 값이 JSON `null`이 아니라 문자열 `"null"`이었다. 디스크 저장을 시도하기 전 입력 검증에서 실패한 것이다.

앱의 문제는 다음 두 가지였다.

1. `search_session.execute`가 후보 저장의 모든 오류를 치명적인 저장 장애로 처리해, 모델이 인수를 고쳐 다시 제출할 기회를 주지 않았다.
2. Codex 완료 이벤트의 최상위 `error`는 null, `status`는 failed였고 구체적 사유는 `result.structured_content.detail`에 있었다. 파서는 이 상세 정보를 읽지 않아 화면에 `failed`만 표시했다.

이 작업은 유사문헌 검색의 MCP 후보 저장 경로를 사용했다. 앞서 수정한 PDF 구성대비 검색의 열람 근거 보존 경로는 이 작업에서 실행하지 않는다. 따라서 관측된 직접 원인은 해당 근거 보존 수정이 아니라 후보 저장 입력 오류에 대한 중단 처리다.

## 수정

- `save_candidates` 도구 스키마에 후보의 `group` 허용값 `A/B/C/null`과 JSON null 표기를 명시했다. 문자열 `"null"`을 임의로 정상 분류로 바꾸지 않는다.
- 입력 검증·후보 식별정보·후보 수 제한 오류는 `SearchLogError`로 구분하고, 이전 저장본이 유지됐다는 안내와 인수 수정 방법을 반환한다.
- 입력 형식 오류는 모델이 수정하여 다시 저장할 수 있도록 한다. 성공 저장 시 앞선 형식 오류는 해소된다. 3회 연속 실패하거나 실행이 끝날 때까지 수정 저장이 없으면 구체적인 사유와 함께 실패 처리한다.
- 실제 파일 저장 실패나 승인 거부는 기존처럼 즉시 중단한다. 기존 후보 저장본을 훼손하거나 검증을 우회하지 않는다.
- Codex 오류의 structured content 또는 JSON text content에서 실제 사유를 읽는다. 최상위 권한·전송 오류가 있으면 그것을 우선한다.

제품 변경 파일: `search_agent_tools.py`, `search_mcp_server.py`, `search_session.py`, `providers/codex_stream.py`.

## 검증

관련 테스트 **126개 통과**. 새 회귀 테스트는 실제 CLI 오류 형태의 상세 복원, nullable group 스키마, 기존 저장본 보존, 잘못된 입력 후 수정 저장, 미해결 입력 오류의 종료 처리, 연속 실패 제한, 저장 장애의 즉시 중단을 검증한다.

실제 실패 실행의 후보 5건을 격리된 폴더에서 재현했다. 원래 `"null"` 입력은 수정 가능한 검증 오류로 반환됐다. 동일 입력의 다섯 번째 group만 JSON null로 고쳐 제출하자 후보 5건 전부 저장됐으며, 마지막 저장 성공 후 미해결 오류도 해소됐다. 실제 stdout 이벤트를 새 파서에 넣어 `failed` 대신 후보 5번의 상세 사유가 복원됨을 확인했다.

재현 결과는 `data/validation/search-checkpoint-20260918/result.json`, 저장본은 같은 폴더의 `reproduction/`에 있다. 외부 모델·검색 API 호출 없이 검증했으며 운영 DB와 기존 실패 이력은 수정하지 않았다. 이번에 전체 검색을 실제 재실행한 것은 아니다.

## 별도 관측 및 적용

같은 검색의 KIPRIS 호출은 코드 `KIPRIS.31`, 이용기간 만료 응답을 반환했다. 다른 채널의 검색은 진행됐으므로 이것이 이번 후보 저장 실패의 직접 원인은 아니다. KIPRIS 검색을 사용하려면 해당 API 활용신청의 기간·승인 상태를 별도로 확인해야 한다.

변경된 백엔드 코드를 일반 검색에 적용하려면 PRISM 재시작이 필요하다. 이미 종료된 실패 실행이 자동으로 이어지지는 않으므로 재시작 후 검색을 다시 실행해야 한다.
