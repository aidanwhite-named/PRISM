이것은 로컬에 보존된 로그 범위의 관측이다. 모든 시점의 전 세계 서비스 상태나
정확한 최초 장애 시각을 뜻하지 않는다.

현재 직접 진단에서는 Google 검색 API가 HTTP 200과 실제 요약을 반환하는데
agy 1.2.2가 선행 빈 thought/text 항목 때문에 no summary로 실패했다. 같은
회사망에서 빈 항목만 제거하면 성공했다. CLI와 Google 응답 형식 사이의 호환
문제가 확인됐지만, 과거 API 응답 원본까지 없으므로 CLI 변경과 서버 응답 변경 중
어느 한쪽만이 최초 원인이라고 단정하지 않는다.

선택 모델도 성공 기록의 gemini-3.7-flash-low와 현재 gemini-3.6-flash-low가 다르다.
이는 도구 선택·출력에 영향을 줄 수 있지만 이 차이만으로 원인이라고 단정할 수 없다.

## 오류별 판정

1. **no summary / 검색 질의 한 건도 응답하지 않음**
   외부 agy 검색 응답 호환 문제에, 9월 12일 추가된 검색 성공 검사가 결합했다.
   검사는 오류를 표시하는 지점이며 Google 요청 자체를 망가뜨리는 코드는 아니다.
2. **grep_search 정책 위반**
   9월 5일 성공 기록에는 grep이 없었다. 오늘은 페이지 저장 폴더를 검색하는
   grep 3회가 기존 정책에 걸렸다. 정책은 9월 9일 뒤에 새로 엄격해진 것이 아니다.
3. **최종 JSON 오류**
   하나의 JSON과 옛 기록 블록을 동시에 요구하던 기존 지시 모순이 드러났다.
   오늘 실패한 두 원본 응답을 9월 6일 parse_payload에 넣어도 둘 다 실패한다.
4. **회사 인증서 / 출처 링크 차단**
   검색 API가 로그인된 요청에 실제 답변을 반환했으므로 no summary의 직접
   원인으로 보이지 않는다. vertexaisearch 출처 링크 차단은 별도의 실제 문제다.

## 9월 14일 이 대화에서 추가한 변경

현재 미커밋 변경은 위 역사와 구분해야 한다.

- agy 1.2.2 검색에만 실행별 loopback 중계와 빈 응답 항목 제거 추가.
- 현재 실행에서 가져온 페이지 파일·전용 폴더만 grep 허용.
- grep의 SearchPath/Query 기록과 성공한 view_file의 열람 판정 보완.
- 옛 출력 블록 지시 제거, 엄격히 제한된 JSON+구형 JSON 기록 조합 처리 추가.

이는 이후 적용한 대응책이지 과거 장애 발생 전부터 있던 변경이 아니다.
짧은 검색 성공 확인을 전체 유사문헌 보고서의 복구 확인과 동일하게 설명한 것은
검증 범위를 과하게 넓혀 표현한 것이었다. 마지막 전체 보고서 성공은 확인되지 않았다.

## 롤백 판단

검색 관련 PRISM 코드만 9월 6일로 되돌려도 현재 agy 실행 파일과 Google의 응답은
그대로다. grep 제한과 출력 지시 모순도 되살아난다. 그러므로 Git 롤백만으로
당시의 성공 환경이 재현된다고 보장할 수 없다.

추가 복구 작업을 한다면, 9월 6일 코드·당시 CLI·현재 CLI를 분리해 같은 입력과
같은 완료 기준으로 비교해야 한다. 비교하지 않은 상태에서 검증 조건을 없애거나
우회를 계속 늘리는 방식은 실제 복구 여부를 흐린다. 이번 조사에서는 롤백·CLI 교체·
모델 호출을 수행하지 않았다.
