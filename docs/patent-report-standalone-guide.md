# 프로그램 보고서에 맞춘 독립 실행용 프롬프트

작성 기준: 2026-10-02 작업 폴더의 현재 V5 지침과 보고서 출력 코드.

사용 파일: [특허 구성대비 보고서 작성 프롬프트](../prompt/patent-report-standalone-prompt.md).

## 기존 프롬프트와 결과가 달라지는 이유

프로그램은 모델의 분석만 그대로 출력하지 않는다. 내장 분석 지침에 구조화 응답 규칙을 붙이고, 원문 문장·위치와 근거 연결을 확인한 뒤 프로그램이 Markdown 보고서를 조립한다. 문제가 있으면 제한된 추가 모델 호출로 근거 선택·연결·대응 판단을 재검토하는 경로도 있다.

사용자가 제공한 프롬프트는 기본 분석 방향은 가깝지만 다음 지점에서 현재 프로그램과 다르다.

| 항목 | 기존 사용자 프롬프트 | 현재 프로그램 기준과 새 프롬프트 |
|---|---|---|
| 구성별 점수 | 주 문헌과 보완 문헌 각각에 점수·등급 | 구성 제목에 인용발명 1 기준 점수 하나 |
| 등급 표시 | 동일 대응·실질 대응·부분 대응 | 동일·실질적 동일·일부 차이·대응 없음 |
| 보완 문헌 | 구성당 최대 1개 | 가장 적합한 하나부터 선택하고 남는 부분이 있을 때만 다음 문헌 추가 |
| 발췌 수 | 문헌당 구성별 1구절, 나머지는 위치만 | 별개의 필수 한정·관계에 필요한 최소 근거를 추가 |
| 외국어 원문 표시 | 전체 번역과 표시 원문 범위를 같게 요구 | 선택 범위 전체 번역 + 약 120자 이내의 확인용 원문 |
| 중복 근거 | 보고서 전체의 재사용 규칙 없음 | E번호로 최초 발췌를 표시하고 이후 구성에서 참조 |
| 근거의 용도 | 대응 근거와 비교 근거의 표시 구분 없음 | 비교용은 `비교 설명:`으로 구분하며 점수 근거로 사용하지 않음 |
| 대응 설명 | 인용발명 기재를 먼저 소개하는 예시 | 청구항의 대상·동작·조건·관계부터 설명 |
| 제목·배치 | 검토 문헌·구성요소 대비·유사점·대응 범위 요약 | 문헌 매핑·청구항 구성별 분석·종합 분석 요약 |
| 차이점 | 별도 유사점 아래 구성별 목록 | 각 청구항의 구성요소 뒤에 잔존 차이만 한 문장씩 |

특히 기존의 **보완 문헌 1개 제한**과 **발췌 1구절 제한**은 서식 차이에 그치지 않는다. 현재 프로그램에서 허용하는 실제 대응 근거를 누락하여 잔존 차이 판단도 달라질 수 있다. 보완 문헌의 점수는 비교 대상이 주 문헌 점수와 달라 같은 보고서 안에서 점수 해석을 복잡하게 만든다.

## 사용 방법

1. 독립 실행용 프롬프트 파일의 본문 전체를 복사한다.
2. 대상 청구항을 붙이고 인용문헌을 첨부한다. 출원 명세서는 역할을 명시하여 별도로 첨부한다.
3. 이전 프로그램 보고서와 같은 문헌 번호를 원하면 그 보고서의 문헌 매핑도 함께 제공한다.
4. 아래 입력 틀에서 해당하지 않는 선택 항목은 지운다. 인용문헌 설명은 실제 첨부파일명과 일치시킨다.

```text
[대상 청구항]
청구항 번호와 (A), (B) 등의 구분을 포함한 현재 청구항 원문

[인용문헌]
- 실제 파일명 1: 인용문헌
- 실제 파일명 2: 인용문헌
- 실제 파일명 3: 인용문헌

[출원 명세서 — 선택]
실제 파일명: 청구항 해석용 출원 명세서

[고정 문헌 매핑 — 선택]
인용발명 1 = 실제 파일명 / 확인된 문헌번호
인용발명 2 = 실제 파일명 / 확인된 문헌번호
인용발명 3 = 실제 파일명 / 확인된 문헌번호

[이전 분석 자료 — 선택]
같은 사건의 이전 청구항과 보고서. 현재 분석의 참고자료입니다.

[사용자 추가 요청 — 선택]
분석할 청구항 범위 등 이번 분석에 적용할 요청
```

프로그램 결과와 비교할 때는 청구항뿐 아니라 문헌·문헌 역할·고정 번호·실제 전달한 원문 범위도 맞춰야 한다. 프로그램이 일부 검색 구간만 읽은 실행과 외부 모델이 전체 PDF를 읽은 실행은 근거 범위부터 다를 수 있다. 같은 구분을 원하면 프로그램 보고서의 구성 기호를 그대로 포함한 청구항을 제공한다.

## 반영 범위와 확인한 한계

새 파일은 외부 대화에서 독립적으로 사용하는 프롬프트다. 프로그램의 내장 지침, 코드, 설정, 저장 보고서는 변경하지 않았다. `prompt/`의 파일을 추가해도 현재 프로그램의 내장 지침을 자동으로 교체하지 않는다.

현재 `task_instructions.py`, `reference_selection.py`, `structured_report.py`와 저장된 보고서 예시의 제목·배치·문헌 표기·등급·근거 참조를 대조했다. 프로그램의 원문 검증·위치 복원·제한된 재검토를 프롬프트의 자체 점검 지침으로 옮겼지만, 이것이 동일한 자동 검증이나 동일한 점수를 보장하지는 않는다. 새 프롬프트로 실제 문헌을 넣어 별도 모델의 보고서를 생성하는 비교 실험은 수행하지 않았다.

검토한 주요 분기:

- 주 문헌으로 전체 구성 대응 → 보완 문헌 없이 종료.
- 보완 문헌 하나로 부족한 부분 대응 → 추가 문헌 없이 종료; 주 문헌 점수 유지.
- 첫 보완 이후에도 다른 필수 한정이 남음 → 그 부분에 실제 대응하는 다음 문헌만 추가.
- 주 문헌 실제 대응 없음 + 보완 문헌 대응 있음 → 주 문헌 0% 유지; 잔존 차이는 별도 판단.
- 주 문헌 판독 불가 → 점수 없이 원문 재확인 필요; 0%와 구분.
- 동일 근거가 여러 구성에 필요 → 첫 구성에서 발췌하고 이후에는 같은 E번호 참조.
- 개별 한정은 확인되나 연결 관계는 미확인 → 전체 관계 대응으로 확대하지 않고 해당 관계를 남김.
