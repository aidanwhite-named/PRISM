## 예산과 별개의 발췌 오류

최종 입력에는 실제 선택 가능한 `S024-T14` 등의 고유 문장 번호가 517개 있었다(지침의 예시까지 포함한 표식 출현 수는 518회). 모델은 E1~E9의 31개 선택 번호를 모두 `ATT-04-P4-T14` 같은 다른 형식으로 출력했다. 31개 중 실제 전달 문장 표식과 일치하는 번호는 0개이며, 저장된 근거 9개 모두 verified=false다.

특히 주 문헌 ATT-04의 4·5쪽 전문은 전달됐다. 이 페이지를 쓰는 E1~E5의 검증 실패를 자료 미전달로 설명할 수 없다. 제공된 번호를 그대로 선택하지 않은 출력 오류다. 지침에는 전체 본문 방식과 검색 방식의 번호 예시가 함께 있어 혼동 가능성이 있지만, 이번 관측만으로 예시 혼용의 인과 효과를 확정할 수는 없다.

번호 앞부분을 일괄 치환해서 복구하는 것은 부정확할 수 있다. 예를 들어 ATT-02 5쪽에는 S013/S014/S015, ATT-05 9쪽에는 S035/S036/S037로 나뉜 원문이 있어 같은 문헌·페이지·T번호만으로 선택 구간을 유일하게 정할 수 없다. 실제 전달 원문과 번역 범위를 다시 대조해야 한다.

현재 실행기는 구조화 보고서의 파싱 오류는 실패 처리하지만 개별 근거 검증 오류는 경고와 함께 보존한다. 해당 경로에는 잘못된 문장 선택을 모델에 다시 요청하는 복구 절차가 없다. 이것이 근거 경고가 대량으로 남아도 전체 실행이 성공으로 보이는 이유다.

## 분석 서술의 별도 문제

A~E 모두 차이가 남는다고 쓰면서 conclusion=supported를 반환했고 검증기가 모순으로 표시했다. 주지관용·설계 변경 설명도 구체적인 연결 이유보다 일반론에 머무는 부분이 있다. 예산을 늘린다고 이 판단 오류가 자동으로 해결되지는 않는다. 이번 조사는 실행·출력 품질 진단이며, 각 구성의 올바른 대응 점수나 차이 해소 여부를 새로 확정한 분석은 아니다.

## 극복 방법과 우선순위

1. **문장 선택 복구부터 보완한다.** 현재 전달 방식에 해당하는 번호 예시만 제시하고, 문헌별 실제 선택 가능 번호를 검사한다. 검증에 실패하면 해당 근거의 번호·번역 선택만 원문과 함께 다시 요청하고 재검증한다. 무조건적인 번호 치환이나 검증 생략은 해결책이 아니다. 근거 확인 상태도 실행 완료 상태와 구분해 표시할 필요가 있다.
2. **현재 agy를 유지한다면 설정을 단계적으로 조정한다.** Settings의 ‘AI 검색 라운드 상한’을 7→12, ‘근거 패키지 최대 문자 수’를 100,000→120,000으로 시도하는 것이 출발점이다. 이는 검증된 최적값이 아니라 이번 관측에 근거한 시험값이다. 실제 입력 크기 안내와 180,000 bytes 전달 상한은 계속 적용한다. 80회 페이지 열람 상한을 늘리는 것은 이번 병목 해소에 도움이 되지 않는다. 재실행에는 추가 시간과 서비스 사용량이 필요하다.
3. **전체 자료가 들어가는 다른 실행 경로를 검토한다.** auto를 유지하고 더 큰 입력을 처리할 수 있는 도구·모델 조합을 선택한 뒤 실행 전 안내에서 실제로 ‘전체 전달’이 선택되는지 확인한다. 이 방법은 검색 후보 누락과 최종 패키지 축소를 줄일 수 있다. 큰 컨텍스트를 가진 모델이어도 동일한 agy 전달 경로의 상한이 유지되면 해결되지 않는다. agy에서 full만 강제하면 이 자료는 입력 초과로 거절된다.
4. **장기적으로 검색과 보고서 작성을 나눠 처리한다.** 주 문헌 전체와 구성별 보완 근거를 나눠 검토하고, 원문 번호·문헌 매핑·공통 조건을 유지한 상태로 종합한다. 이월 후보를 모두 읽은 뒤 부족한 구성만 추가 검토하는 방식도 필요하다. 기존 보고서 요약만 연결하면 원문 누락 문제가 이어질 수 있다.

예산 확대만으로 개선되는 정도와 분석 품질 향상은 새 비교 실행 전에는 확정할 수 없다. 이번에는 설정·제품 코드·원 보고서를 변경하지 않았고 모델을 추가 호출하지 않았다.
