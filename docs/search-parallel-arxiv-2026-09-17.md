# arXiv 초기 병렬 검색

`start_collection`에 모델이 작성하는 `arxiv_query`를 추가했다. 첫 라운드 지침은 EPO·KIPRIS·OpenAlex·arXiv를 시작하고, 기다리는 동안 네이티브 웹 검색을 수행하도록 한다. 사용할 수 없거나 불필요한 출처는 기존처럼 이유를 남기고 생략할 수 있다.

API 작업자는 4개이며, arXiv 검색은 OpenAlex의 논문 검색 잠금과 분리했다. 두 요청은 모두 기존 `literature_search` 도구를 이용하지만 수집 결과는 기존 OpenAlex 키 `literature_search`와 새 arXiv 키 `arxiv_search`로 구별한다. 도구 원본 기록에는 각각의 `source`를 보존한다. arXiv 의존성이 없으면 해당 출처만 건너뛰고 사유를 반환한다. 진행 표시에도 arXiv를 포함한다.

검증은 네 API 작업의 동시 진입, 실제 도구 디스패치에서 OpenAlex·arXiv의 겹치는 실행, 독립적인 결과 보존, KIPRIS 실패 격리 및 arXiv 의존성 누락 처리를 포함한다. 실제 외부 API로 새 검색을 실행한 것은 아니다. 실행 중인 서버는 재시작해야 새 프롬프트와 진행 표시가 적용된다.

## 직전 특허 검색 진단

실행 `8e59e9ee-c7b1-40fc-95cc-4ce5bc89df62`에서 KIPRIS는 `KIPRIS.31` 이용기간 만료로 실패했다. EPO는 독립적인 세 검색식 모두 0건을 반환했다. 해당 EPO 404는 검색 결과 없음 fault를 확인하여 0건으로 처리한 응답이며, KIPRIS 만료에 따른 연쇄 오류가 아니다. 제목·초록에서 여러 단어를 모두 요구하는 검색식이므로 질의가 너무 제한적이었을 가능성이 있으나, 완화 질의 비교 실험으로 확정한 원인은 아니다. KIPRIS 갱신만으로 전체 특허 검색 품질이 해결된다고 판단할 수 없다.
