# 검색 누락 보완과 공개문헌 발견 검증 (2026-09-13)

공개번호를 질의에 넣지 않은 EPO 키워드 검색으로 KR20260093229A가 실제 응답에
포함되는 것을 확인했다. 모델이 실패했던 질의를 그대로 재생해 새 보완 로직을
검증했다. 전체 구성대비 보고서를 다시 생성한 검증과는 구분한다.

## 변경

- 웹 검색은 최초 탐색에서 실제로 시도하도록 지시하고 미수행을 보고서 제약에 표시한다.
  연결 미확인을 사용 불가로 해석하지 않는다. MCP에 현재 Provider를 전달한다.
- Codex 호출 완료는 성공과 분리해서 기록한다. 본문 열람 성공·인용 검증 등급을 올리지 않는다.
- EPO `start`/`next_start`, 전체 건수, 조회 범위, 미탐색 범위를 제공한다.
  날짜 제한이 없으면 임의 기준일을 만들지 않는다.
- 같은 EPO 질의·페이지는 실행 내 원장으로 재사용한다. 다른 질의의 중복 문헌은
  번호로 참조하며 본문을 다시 보내지 않는다.
- 후보 선별 응답은 제목·초록 한 언어, 출원인·공개일·분류만 보낸다. 초록은 700자로
  제한하고 잘림을 명시한다. 원본과 근거 참조는 유지하며 필요한 후보는 fetch로 조회한다.
- 잘린 초록과 그 전문이 일치하면 출처 충돌로 처리하지 않는다. 다른 전문끼리의
  차이는 여전히 충돌로 처리한다.
- 명세서 첫 페이지의 공개번호를 추출하여 EPO 실제 응답과 대조한다. 키워드 발견,
  분류만 발견, 번호·인명 검색만 발견, 미발견을 구분한다. 최종 후보에 모델이
  번호를 적은 것만으로는 통과하지 않는다. 웹 결과 본문은 자동 대조 대상이 아니다.

## 제한된 자동 보완

프롬프트 수정만으로는 모델이 직역 단어를 반복하거나 `any`를 넓게 사용하는 문제를
충분히 해결하지 못했다. EPO가 1,000건을 초과해 돌려주고 이전 검색과 겹치는 단어 및
새 대안 단어가 함께 있는 경우, 새 대안만 따로 검색하는 보완 질의를 최대 한 번 한다.
`any` 동의어 목록만 바꾸며 필수 `all` 개념은 삭제하지 않는다. 필요하면 이전 질의의
필수 핵심 개념 한 개를 추가해 기술 분야를 유지한다. 도메인별 동의어 사전이나
해당 공개번호·분류코드를 코드에 넣지 않았다.

이는 단일 모델 실행 내부 검색 도구의 제한된 질의 보완이다. 별도 LLM 호출·독립
에이전트·후보 선정/순위 변경은 없다. 추가 OPS 호출은 동일한 MCP 호출 예산과 쿼터를
사용하고 별도 시작/완료 원장에 기록한다. 보완 실패 시 원래 성공 결과는 보존한다.

## 실제 검증

번호를 가린 명세서 참고 자동 진단에서 모델이 생성한 질의:

1. `ta any "audio music sound" and ta all "video generation"`: 6,589건.
2. `ta any "music musical audio" and ta any "movement color"`: 21,986건.

당시 앞의 5건씩만 받은 결과에는 대상 공개문헌이 없었다. 위 질의를 새 도구에
그대로 재생하면, 두 번째 질의의 반복된 `music audio`를 제외하고 이전 핵심 개념을
유지한 다음 보완 질의가 자동 실행된다.

`ta any "musical" and ta any "movement color" and ta all "video generation"`

실제 응답 5건의 첫 문헌이 **KR20260093229A**였다. 나머지는 WO2023210388A1,
WO2022154050A1, KR20220032890A, US2019147229A1이다. 번호·출원인·날짜 조건은 없다.
실제 원장과 응답 참조는 `%LOCALAPPDATA%/PRISM/diagnostics/recall-replay-20260913-final/`
에 보존했다. 모델이 새로 질의를 만드는 전체 실행을 매번 성공한다고 보증하는 결과는 아니다.

별도 수동 대조 질의 `ta any "music musical" and ta all "video" and ta any "motion movement color"`
에서도 대상이 발견됐다. 자동 보완 검증과 수동 대조를 혼동하지 않는다.

## 비용과 검증 범위

동일한 실제 문헌들의 기존 전체 응답과 선별 응답을 오프라인 비교한 결과,
JSON 문자는 86,352자에서 42,262자로 **51.1% 감소**했다. 이는 응답 크기 비교이며
전체 실행 토큰·요금의 동일한 감소율을 뜻하지 않는다. 중복 문헌 제거에 따른 추가
절감은 이 수치에 포함하지 않았다.

`backend/scripts/probe_search_recall.py`는 저장된 실행의 청구항으로 제한된 실제
검색을 진단한다. `--with-spec`는 번호를 가린 명세서를 참고하고, `--initial-only`는
웹 1회와 초기 EPO 2회까지만 검증한다. 이 진단은 계정 사용량을 소비하므로 반복
검증은 가능한 한 저장된 질의를 도구에 재생해 수행한다.

검색·API·날짜·쿼터·Provider·근거 검증 회귀 테스트 **409개 통과**, 프론트 빌드 성공.
기존 서버 종료를 포함한 재시작 명령은 자동 승인 정책에 차단됐다. 이후 기존 서버가
종료되어 포트가 비어 있음을 확인하고, 종료 명령 없이 수정된 서버를 8765 포트에
새로 시작했다. 이전에 저장된 보고서는 다시 생성하지 않았다.
