# 인용 경로와 자동 검색 실패 확인

2026-09-17. 제품 코드는 변경하지 않고 기존 어댑터를 실제 호출했다. 알려진 문헌을 넣은 진단이며 청구항만으로 발견한 성과로 계산하지 않는다.

## 실제 인용 검색

| 입력과 방향 | 기존 EPO 어댑터 결과 |
|---|---|
| WO2012111622A1 → 피인용 | 2건. 첫 번째가 JP7475618B1, 두 번째 CN113129414A |
| WO2012111622A1 → 인용 | JP2010170279A, JP2006323804A |
| US9208613B2 → 피인용 | 12건. JP7475618B1 없음 |
| JP7475618B1 → 인용 | 0건 |

JP7475618B1의 EPO 서지 원본은 해당 공개문헌 한 건이며 `citation`과 `patcit` 태그가 모두 0개다. Google Patents 페이지에는 WO2012111622A1이 인용문헌으로 표시된다. 현재 인용 어댑터는 이런 경우 다른 출처로 보완하지 않는다. EPO의 한 응답에서 인용이 없다는 사실은 실제 인용 관계가 없다는 뜻이 아니다.

WO2012111622A1과 US9208613B2는 동일 패밀리지만, 현재 단일 공개번호 피인용 검색의 결과는 다르다. 현재 코드는 family_id 저장과 중복 조정을 하며, 패밀리 전체 공개문헌을 먼저 열거하고 인용/피인용을 합치는 기능은 현재 검색 경로에 없다.

## 자동 실행에서 호출되지 않은 이유

- 기존 및 개선 실행 기록에는 citation 경로와 citation edge가 없다.
- `Engine.run()`은 `discover()` (DB 조회와 웹 탐색)가 끝난 뒤 수집 단계의 잔여 시간이 10초보다 많을 때만 `expand()`와 `search_citations()`를 호출한다.
- 해당 실행들은 웹 탐색이 수집 시간을 소진했다. 인용 함수 자체가 호출되지 않아 `citation_stage_skipped` 이벤트도 남지 않는다.
- 함수가 호출되더라도 잔여 시간 35초, 질의·호출·문헌·토큰 예산 조건을 추가로 검사한다.
- 특허 출발점도 없었다. EPO 초기 질의는 0건이고 웹 후보는 0건이었다. 저장된 후보는 논문이었다.
- 함수는 최대 특허 1건·논문 1건에서 한 단계만 추적한다. 특허의 인용문헌은 현재 앞 3건, 피인용 결과는 첫 20건까지다. 이 제한이 이번 WO 누락의 직접 원인이라는 증거는 없다. 이번 실행은 그 이전 단계에서 멈췄다.

## 웹 오류 해석

관측된 오류는 Gemini CLI가 `vertexaisearch.cloud.google.com/grounding-api-redirect/…`를 읽을 때 받은 `malformed HTTP status code`와 `차단페이지` HTML이다. Google의 봇 판정이라고 확정할 근거가 없다. Google 원문 주소는 같은 PC의 프로그램에서 접근됐다. 중계 경로·클라이언트·네트워크 장비 중 어느 구간이 문제인지는 별도 응답 헤더/네트워크 진단이 필요하다.

Google은 [자동 트래픽 차단](https://support.google.com/websearch/answer/86640?hl=en)을 설명하지만, [프로그램용 Google Search grounding](https://ai.google.dev/gemini-api/docs/google-search)도 제공한다. 일반 정책의 존재만으로 이번 오류 원인을 판정할 수 없다.

## 개선 설계

1. 모델이 질의·도구·다음 원문을 선택하는 반복 탐색을 지원한다. DB를 반드시 먼저 모두 조회하게 하는 순서를 없애되 검색 도구 자체는 유지한다.
2. 검색 도구 응답의 제목·URL·식별자를 앱이 직접 받는 즉시 저장한다. 모델의 마지막 JSON만 기다리지 않는다. 현재 CLI가 결과 본문을 노출하지 않는 경로는 결과를 받을 수 있는 검색 어댑터로 보완해야 한다.
3. 유망 특허를 확보하면 패밀리 열거 및 양방향 인용 작업을 대기열에 넣고, 추가 키워드 탐색이 그 작업의 시간을 소진하지 못하도록 한다.
4. 패밀리 구성원별 인용 관계를 모으되 관계의 원래 공개번호와 출처를 보존한다. 비어 있는 EPO 인용 정보는 공개 원문 등 다른 출처로 보완한다.
5. 120초에 미완료이면 저장한 후보와 대기 작업을 보여주고 미완료 상태로 명시한다. 이어 검색 시 남은 작업을 실행한다.
6. 청구항만 넣어 WO/JP를 발견하는 시험과, WO를 명시적으로 넣어 JP로 확장되는 시험을 분리한다. 알려진 번호를 초기 질의에 섞지 않는다.

위 설계는 이번 진단에서 제품 코드에 적용하지 않았다.
