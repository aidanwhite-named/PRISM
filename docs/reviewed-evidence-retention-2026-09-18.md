# 열람 근거 보존 수정 및 검증

## 적용한 수정

독립적인 검색 모델 호출 사이에 구성별로 실제 전달한 `read_chunk`, 페이지·단락 열람 원문을 보존한다. 다음 호출에서는 그 원문을 결과 앞쪽에 다시 싣고 남은 공간으로 새 검색 결과를 전달한다. 새 검색의 상위 후보 목록이 달라져도 이미 읽은 원문은 없어지지 않는다.

같은 원문이 여러 구성에 필요한 경우 구성 연결은 각각 남기고 본문은 같은 입력 안의 참조로 공유한다. 이전 호출의 검색 결과에 대한 참조를 그대로 저장하지 않고 매 호출에서 재구성한다. 페이지 본문은 기존 캐시를 사용하며 자동 재전달은 새 페이지 열람으로 집계하지 않는다. 응답 JSON 파싱에 실패한 다음 호출에도 보존된 원문은 다시 전달한다.

**기존 라운드 반환 예산 64,000자는 늘리지 않았다.** 보존 원문을 먼저 계산하고 새 결과를 남은 예산에 맞춘다. 후속 호출에도 원문을 온전히 보존할 공간이 부족한 새 열람은 미전달로 이월한다. 원문을 잘라서 열람 완료로 기록하지 않는다. 그만큼 새 검색에 쓸 공간이 줄 수 있으며, 기존 이월·범위 제한 기록에 반영한다.

보존은 관련성 판정이 아니다. 마지막 모델이 근거를 선택하거나 제외하는 권한은 유지한다. 최종 선택한 근거를 주변 페이지보다 우선 보존하는 처리는 `evidence.fit`에 이미 있어 중복 구현하지 않았다. 검색 프롬프트, 단락 파서, 청구항 분해, 검색·최종 근거 예산은 변경하지 않았다. 혼잡 복구와 호출별 출력 격리도 유지했다.

제품 변경은 `backend/app/retrieval/agent.py`에 한정했다. 신규 회귀 테스트는 `backend/tests/test_reviewed_evidence_retention.py`이며 기존 페이지 캐시 테스트 한 곳은 자동 보존 행을 구분하도록 조정했다.

## 원래 실패 사례 재현

원래 문제 실행 `69911dce-8b35-406e-9aeb-f3ad0b122f16`의 색인과 저장된 모델 응답을 이용해 외부 모델 호출 없이 검색 루프를 재현했다.

- 이전에는 구성 D에서 읽은 `ATT-04 / P0011-002`가 마지막 입력에 없었다.
- 수정 후에는 구성 D의 보존 열람 결과로 마지막 입력에 남는다. 아틀라스 원문의 `블록(830)`도 포함된다.
- 마지막 결과는 **63,303자 / 64,000자**, 보존 열람 항목은 14개였다.
- 저장된 최종 선정 응답도 그대로 재생했으므로, 이 실험은 모델이 새롭게 근거를 선택했다는 증명이 아니다. 전달 손실의 재현과 수정 검증이다.

스크립트와 결과: `data/validation/reviewed-retention-20260918/replay.py`, `offline/result.json`.

최종 모델 출력은 종료 코드 0, 오류·도구 호출·승인 거부 없이 생성됐다. 검색 호출은 각 1회 시도로 성공해 혼잡 재시도는 사용되지 않았다. 다만 출력 끝의 문헌 매핑 프로토콜은 종료 표시가 누락됐다. 구성 분석 블록은 파싱됐지만 보고서 전체 후처리·후속 분석 연계까지 정상화됐다고 볼 수는 없다. 비교용 `report.md`는 기계용 꼬리 부분을 제거한 읽기용 사본이며, 원시 `model_report.md`는 보존했다. 이 별도 출력 형식 문제는 이번 수정 범위에 포함하지 않았다.

## 검증과 남은 범위

관련 백엔드 테스트 **218개 통과**. 새 테스트 7개는 재검색 이후 보존, 구성별 연결, 이전 호출 참조의 재구성, 페이지 캐시와 집계, 기존 예산 준수, 미전달 열람의 상태 오염 방지를 확인한다.

이번 수정으로 재현·검증한 것은 열람 원문의 전달 손실이다. 실제 모델 비교는 조건당 한 번이므로 평균 품질 향상을 보장하지 않는다. 단락번호 인식, 전제부 분해와 누락 검사, 검색 자체의 충분성, 출력 형식 문제는 별도로 남는다. 운영 서버는 자동 reload 없이 실행 중이므로 일반 보고서 생성에 소스 변경을 적용하려면 PRISM을 재시작해야 한다.
